# DINet 消费提前量实验 · 2026-09-19

在当前部署的独立实验进程中，给音频消费者保留0.4秒提前量，消除了固定输入下反复出现的供帧停顿。默认播放器未改变：三次短句的最大音频调度空隙从128–133ms降至未观察到大于1ms的空隙。这个结果是媒体供给节奏的改进，不是模型算力加速或整体对话时延提升。**原服务默认设置尚未修改。**

## 单变量干预与失配对照

[上一轮归因](DINET-DELIVERY-ATTRIBUTION.md)发现消费者快速处理五个200ms块后，会等待到 `start + blocks × 0.2`，失去原有输入提前量。本轮仅把等待公式改为 `start + blocks × 0.2 − lookahead − now`，保留首次五块和正等待条件；比较0、0.4、0.8秒。模型、角色、客户端1秒预送、JPEG编码、播放器120ms预缓冲不变。

首轮直接连worker时默认协商了WebSocket压缩，而原代理到worker使用 `compression=None`。这使帧体平均接收耗时约40–45ms，供帧停顿被持续的传输开销掩盖。首轮10次记录完整保留，**不纳入优化收益估计**。统一关闭压缩后，正式对照重新复现了原停顿。

正式实验预热一次，同一进程内按0→0.4→0.8交错重复三次。绕过原代理，原生消费者源文件指纹固定，独立入口不注册生产心跳，仅在本进程修改表达式；原文件未改动。GPU容量由临时释放一个空闲worker缓存提供，控制器及独立超时恢复逻辑保证实验结束恢复该worker。此实现针对既有自定义服务，不泛化为DINet官方代码缺陷。

## 适配器观测

同一2.432秒中文PCM，每轮61帧，完整输出PCM与原输入一致。帧编号从0开始。

| 提前量 | 三次帧头19→20间隔 | 首配对媒体范围 | 消费后输入队列快照最大值 |
| --- | --- | --- | ---: |
| 0秒 | 264.7 / 293.9 / 262.4ms | 61.0–64.5ms | 7 |
| 0.4秒 | 39.7 / 39.7 / 39.1ms | 53.2–87.8ms | 5 |
| 0.8秒 | 38.9 / 36.4 / 39.2ms | 64.2–70.8ms | 5 |

0.4秒是本次能消除停顿的最小已测提前量，不是全局最优值。首媒体包括连接、生成、传输和编码，没有稳定的首媒体收益证据。队列值只在消费块后读取，不能证明整个系统的队列峰值或内存占用；理论等待值在前四块和非正值时不会实际执行睡眠。

## 默认浏览器播放器对照

同一实验进程内复用生产 `AvatarPlayer`、`Timeline` 和2D渲染器，浏览器预热一次后交错比较0与0.4秒。小于等于1ms的浮点/调度误差不计空隙。

| 输入 | 原设置最大空隙 | 0.4秒提前量最大空隙 |
| --- | ---: | ---: |
| 中文短句，第1轮 | 133.3ms | 0ms |
| 中文短句，第2轮 | 128.0ms | 0ms |
| 中文短句，第3轮 | 128.0ms | 0ms |
| 同一短句重复4次，9.728秒 | 176.0ms | 0ms |
| 含400ms停顿，5.008秒 | 138.7ms | 0ms |

10次正式播放均完成，计划播放的样本数与输入一致。长片段与停顿各只有一组，属于覆盖检查；重复拼接不是自然长对话。`0ms`表示这次AudioContext调度记录没有超过阈值的空隙，不代表物理扬声器录音无缺陷或视觉零跳帧：两种设置的停顿样片都实际展示125/126帧；长片段原设置展示243/244帧，提前量设置244/244帧。首个音源的调度调用约在播放请求后111–134ms，未增加播放器预缓冲；该调用不是物理首声时刻。

另在适配器层对0.4秒配置做三次第30帧后取消及完整恢复，全部通过。停止连接到观察原生零连接/零消费者约23.5 / 33.7 / 25.4ms，包含轮询和HTTP查询；它不等于精确GPU抢占时延或显存释放。输入队列之外的缓冲尚未连续采样。

## 固定输入的内容回归

暖态服务保留角色视频状态：即使都使用0秒提前量，不同请求的同位置JPEG也不一致，不能把这种差异归因于节奏调整。因此另起两个独立新进程，分别用0与0.4秒捕获相同中文输入。

这两个捕获的**61帧JPEG逐字节一致、PCM一致、元数据与时间戳/样本区间一致，捕获fingerprint完全相同**。此前三个新进程的0秒首条请求也得到相同的61帧哈希。这证明本条输入的输出内容回归通过，不替代其他输入或实际音素口型质量评估。两个质量进程的启动/退出日志已归档；新进程及首请求条件来自执行记录，质量报告未单独持久化请求前的原生计数，不能仅由捕获fingerprint推断该条件。

## 复现边界与下一步

仓库提供[参数化隔离入口](../evaluation/dinet_pacing_lab.py)，调用已安装的特定自定义服务代码，不分发其模型、人物、服务实现。原生worker完整文件SHA不匹配时拒绝启动；不能直接用于官方DINet仓库或任意不同部署。

```bash
# 在具备该已审计服务及依赖的环境启动独立进程。
python evaluation/dinet_pacing_lab.py --native-root /path/to/native-service --port 18427
```

`GET /experiment/status`返回实验进程PID、源文件SHA及块级记录；原生连接路径仍为 `/ws/<实验PID>/<已配置角色>?lead=0.4`。实验客户端必须设置 `compression=None`，先分别预热、正式重复，再独立捕获媒体。默认仅绑定回环地址。测试入口不注册生产代理，不应用到默认服务进程；其记录用于一次有界实验，结束后关闭进程。

本轮实际临时控制器、独立恢复脚本、浏览器驱动和原始记录已按SHA归档到本地实验目录；包含部署地址的控制器及原媒体不进入源码包。发布入口仅把固定根目录/绑定地址/端口参数化，已在相同安装环境验证启动及源SHA，未把这次无推理启动冒充额外性能样本。机器记录保留[正式、失配与扩展实验](benchmarks/2026-09-19-dinet-pacing.json)。

局限：同一GPU、单个角色、固定循环次序而非随机顺序；原代理路径、实际麦克风声学效果、长时间通话及更广泛内容质量仍待验证。下一步把通过验证的策略整理为可配置集成，在原代理路径复测后再决定默认启用；完整阶段目标仍含视觉输入与后续方法实验。
