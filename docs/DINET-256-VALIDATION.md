# DINet 256 人物部署验证

2026-09-20，在已有服务上切换人物并实测。256指模型的人脸输入宽度；浏览器输出保持360×640、25fps，不是256×256的整幅视频。人物素材和权重来自部署者已有资源，未训练新模型，也不随源码发布。

## 配置与故障定位

服务使用固定人物模式，修改WebSocket路径不足以更换实际模型。本次同时选择匹配的256权重、动作与参考帧，并在有源码指纹保护的本机启动器中将推理工厂输入宽度设为256。参考目录的只读缓存缺失，通过选择已有缓存且四张参考JPEG逐字节相同的目录解决，没有改写人物数据。

较大的原始视频帧暴露既有代理20条消息队列的丢包问题：原生日志出现QueueFull，客户端按协议拒绝截断的帧。部署适配改为有界队列等待；同时在退出worker连接前取消并等待全部转发任务，将worker连接关闭等待配置为0.5秒。仅加队列等待会在客户端断开时遗留阻塞任务，归档原函数的断开、连接关闭、超时三条离线路径均复现并验证清理修复。离线测试不能证明真实网络关闭耗时。

共享24GB显卡上，多份256 worker与其他模型同时驻留触发显存不足；实际部署改为单worker，适配当前页面单会话限制。应用仅重试首元数据前明确的容量不足关闭，不重试显存或模型错误。原有0.4秒消费提前量保持。本次原生源文件未修改，角色工厂和代理补丁均由本机指纹校验启动器在进程内应用；后续已将同一逻辑整理为可配置的[worker与代理启动入口](../dinet-server/README.md#固定256人物与代理背压)，原生实现和素材仍需由部署者提供。

## 验证结果

| 检查 | 实测结果 |
| --- | --- |
| 连续三次同PCM生成 | 每次61帧、58368个24k样本，原PCM完整保留 |
| 暖模型首媒体等待 | 0.155 / 0.203 / 0.283秒；从适配器请求开始，不包含ASR、LLM和TTS |
| 打断后立即请求 | 完整恢复61帧，首媒体1.625秒；包含等待单worker释放 |
| 真实网页文字对话 | 渲染338帧，配置男声，回复结束与断开后均播放循环idle |
| 待机视频 | 5秒、125帧；生产文件与验证产物SHA一致 |
| 回归测试 | 部署应用13项、开发分支14项通过；新增3项覆盖忙碌重试、模型错误传播与可取消性 |

本机原始成功和失败记录分别保存在 `artifacts/kanghui-switch-20260920/`，最终协议记录为 `speech-cleanup/results.json`，浏览器记录为 `browser/results.json`。人物图像、原生服务源码副本与机器配置不进入源码仓库。

这次验证不证明物理麦克风、扬声器或人工口型质量。单worker并发能力、容器重新创建后的配置恢复和独立GPU主机安装仍需单独验证。原有阶段验收缺口继续保留，见[验收表](ACCEPTANCE.md)。

## 可配置入口复验

同日将运行补丁整理为源码中的可选人物配置与独立代理启动器，在相同现有服务上替换启动命令并重启。启动文件固定快照与待提交源码逐文件SHA相同；没有复制原生服务。8项CPU配置/重写/消费节奏检查、归档原函数的3类清理检查与独立代码审查通过。

新入口连续三次完整生成61帧/58368样本，首媒体分别为2.265秒（冷加载）、0.204秒和0.266秒；打断后恢复61帧，首媒体1.626秒。网页真实文字回复渲染335帧，回复后及断开后循环idle均通过。服务回到1个空闲worker、0个代理连接。该复验说明发布入口重建了现有部署行为，不是新增性能优化对照；冷启动不混入暖模型数值。

本机记录位于同一实验目录的`portable/`，其中保存部署前后命令、固定快照清单、成功生成、浏览器检查和服务状态。生产已保留新命令，旧命令留作回退。容器重建及空白主机验证仍保持未完成。
