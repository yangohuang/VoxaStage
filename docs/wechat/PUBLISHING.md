# 首批三篇发布操作

交付的是可编辑稿件和离线素材包，尚未连接微信公众号后台。每周三20:00为建议排期，不是已创建的自动推送。账号名称、署名和首次发表日期以实际账号设置为准；源文件没有编造这些信息。

## 构建与预览

Python 3.11+，需要 Pillow 和 Python-Markdown。当前验证版本记录在交付说明。制图脚本使用系统的 Noto Sans CJK SC 字体，可通过 `--font` 指定本地中文字体文件。图源与PNG均已提供，阅读或上传不需要先重绘。

```bash
python docs/wechat/tools/render_assets.py
python docs/wechat/tools/build_package.py
python docs/wechat/tools/check_package.py
```

打开生成的 `build/index.html`，分别检查三篇完整稿。HTML使用内联正文样式，不加载外部字体、脚本或统计服务。用390px手机宽度检查图中文字、长链接、段落和标题，再在公众号后台检查最终版；浏览器检查不能代替平台检查。

发布包 `build/voxastage-wechat-batch-01.zip` 内含离线HTML、PNG/SVG、源稿、后续简报与SHA256清单。解压后打开 `index.html` 即可阅读。`source/`保留可编辑原稿；已有PNG不依赖模型或GPU。

## 把一篇稿件移入公众号

1. 在实际账号后台新建图文草稿。从原稿顶部取标题、摘要和封面文案；作者署名用账号拥有者实际希望展示的名称。
2. 从HTML阅读版复制正文及参考资料。页面顶部的封面可用于阅读，但作为正文装饰图是否保留按排版选择；上传封面使用对应的 `assets/01-cover.png` 等文件。
3. 逐张上传两张正文PNG，按图注位置替换。不要假设复制本地HTML会自动把图片上传；后台预览必须能独立显示图片。
4. 公众号不支持或不保留的普通外链，改成可读的参考条目并保留来源地址；若账号具备“阅读原文”入口，可设置为系列仓库目录。不要伪造微信文章URL。
5. 首次发布时，尚未发表的下篇链接显示为“下篇预告”，不冒充已发布内容。源码包里的本地导航用于离线阅读；已发表的公众号链接后续回填到 `series.json`。
6. 后台手机预览核对标题、封面裁切、图片、字体、链接、摘要和作者后，按既定人工排期发布。当前交付没有替账号创建草稿、排期或群发。

封面画布为1080×460，核心标题与副标题放在内边距内；如后台需要其他裁切比例，另行预览，不承诺自动裁切后的显示效果。

## 发布前逐篇检查

- [ ] 标题、摘要、封面文字与正文范围一致，没有用未来能力吸引点击。
- [ ] 每个功能事实能回到固定版本源码或已记录实验，上游归属明确。
- [ ] 所有数字说明测量边界与样本，未新增虚构实测或将回放称为在线。
- [ ] 两张正文图在手机上可读；图注清楚标记技术示意图。
- [ ] 私人地址、工作信息、凭据、会话内容已排查；人物与声音素材有公开依据。
- [ ] 本地链接已替换为可用平台链接或明确的文章预告，引用来源仍可追溯。
- [ ] 发布后将实际链接与时间写入 `series.json`，更新目录，再记录复盘数据。

前三篇是机制解释文章，使用原创示意图，不附伪造的实机演示。04–06、08–09效果篇需按各自简报补15–40秒真实演示；视频尚未制作，不算当前交付内容。

## 排期与维护

先备齐三篇再开始周更，每次发布后保证下一篇仍有完整稿与素材。第4、8、12篇后复盘。原理篇与实证篇可以交错，独立实验尚未成熟时使用储备专题，不将正文写成占位模板。

固定版本引用说明文章对应的实现；未来代码变更不倒改旧实验成绩。发现实质错误时维护勘误记录，并在平台允许范围内修正文案。文章与图片采用仓库集成层许可；第三方源码、模型和素材继续遵守各自许可，见仓库的 THIRD_PARTY.md。
