## 发布安排

先完成 01–03 三篇存稿的发布前检查，再启动每周三 20:00（北京时间）的人工排期。这里是编辑建议，不是已经创建的定时发布任务。

| 阶段 | 建议内容 | 执行规则 |
| --- | --- | --- |
| 启动前三周 | 01 → 02 → 03 | 从系统地图进入设计取舍和技术深度 |
| 第四至七周 | 04 → 05 → 06 → 07 | 每篇仅讲一个独特问题，避免重复安装教程 |
| 后续五个主线周 | 08 → 09 → 10 → 11 → 12 | 逐篇满足证据门槛后再排期 |
| 储备插入 | S1 / S2 / S3 | 主线证据未成熟时插入，主线编号不变 |

按素材成熟度，主线通常跨12–15周；不是承诺全部后续功能在第12周完成。JEV默认只作为可选决策对照，不改变本地优先方向。后续分支中的动作能力先核对代码版本和验收，再决定写入哪一篇。

每发布四篇，用 [复盘模板](RETROSPECTIVE.md)记录可获得的平台数据、技术提问与复现反馈，不把阅读量当作技术正确性。03、07、11三篇代表作实际完成后，再在仓库首页增加精选文章导航。

## 文件与使用

- `articles/`：正文、摘要、封面文案、引用与导航；正文用明确标记分隔，便于统计。
- `assets/`：三张封面、六张正文图；PNG供上传，SVG可编辑。全部为本项目原创技术示意图，无肖像、声纹或私人截图。
- `briefs/`：后续选题简报，不是填了标题的伪成稿。
- [发布操作与验收](PUBLISHING.md)：浏览器预览、复制正文、上传图片、来源核验及公众号排期。
- [来源证据索引](EVIDENCE.md)：正文事实对应源码和实验边界。
- [执行记录](DELIVERY.md)：检查结果与仍需在公众号后台完成的步骤。

在仓库根目录执行（Python 3.11+；本地字体与工具依赖见发布说明）：

```bash
python docs/wechat/tools/render_assets.py
python docs/wechat/tools/build_package.py
python docs/wechat/tools/check_package.py
```

生成 `docs/wechat/build/index.html` 浏览器阅读入口、三篇独立HTML和 `docs/wechat/build/voxastage-wechat-batch-01.zip` 发布包。生成物不作为源码提交；包内含校验清单。页面与图片均可离线阅读，不需要模型服务、账号或外部脚本。

公众号编辑器是否保留样式、外链如何展示，以实际账号后台为准。当前未连接该账号，发布包不代表已上传草稿或已群发。
