# 自动语音打断基线 · 2026-09-19

两条对话后端分别搭配三种数字人，六个组合均观察到声音触发的轮次切换、正在播放的旧音源停止、新回复播放，以及已观察片段排空后进入idle。没有调用按钮打断或发送文本命令。在线服务未改动。

这项结果验证交互控制，不代表回答质量全部通过。三条级联记录正确识别了“停一下，只说你好”，但最终回复均为“好的，我只说‘你好’”，违反严格的简短输出要求；三条端到端记录的最终文字为“你好”或“你好。”。这是一个固定问题下的对照样本，不能由三种渲染器下的重复观测推断两种模型的总体能力差异。

## 输入与测量边界

在现有浏览器页面连接前安装`evaluation/browser-probe.js`和`evaluation/voice-round.js`，物理麦克风关闭。使用同一份16kHz、单声道、有符号小端PCM16输入，按20ms（320样本）一包直接发到真实会话WebSocket；最后一包允许不足320样本。

| 输入 | 合成提示词 | 样本数（含尾部1秒静音） | 包数 |
| --- | --- | ---: | ---: |
| first | 请详细介绍实时语音交互技术，包括语音识别、大模型生成和语音合成。 | 113621 | 356 |
| second | 停一下，只说你好。 | 50133 | 157 |

输入由本地TTS生成，24kHz重采样为16kHz，追加16000个零样本。提示词没有经过人工逐句听写核对。WAV和PCM摘要、每个发送包的样本区间与浏览器单调时钟见[机器记录](benchmarks/2026-09-19-voice-interruption.json)。原始音频只保留在部署者本地，不随源码导出。

第一段输入后，等待实际播放、至少5个渲染帧和非空音源队列，再发送第二段。级联链路的自动reset原因是`interrupted`，端到端链路是`speech_started`；判定同时要求generation增加、至少一个旧音源被显式停止，以及没有手动控制命令混入。额外核验每组都存在reset时处于计划播放区间的旧音源被停止，且reset后没有旧generation新建音源。

| 后端 | 数字人 | 第二段首包→reset | reset→最后一次旧音源stop调用 | 被停止旧音源数 | 严格“只说你好”文字约束 |

| 级联 | FlashHead | 562.3ms | 0.1ms | 10 | 未通过 |
| 级联 | DINet | 559.6ms | 0.1ms | 2 | 未通过 |
| 级联 | StreamingTalker | 561.1ms | 0.0ms | 8 | 未通过 |

| MiniCPM-o | DINet | 559.3ms | 0.1ms | 2 | 通过 |
| MiniCPM-o | StreamingTalker | 556.7ms | 0.1ms | 11 | 通过 |

首包→reset包含输入内容起始、VAD、服务端处理和传输，不能称为纯VAD延迟或麦克风采集延迟。`stop`是JavaScript调用；0.0ms是时钟精度和四舍五入结果，不是零声学延迟。运行环境为headless Chromium和SwiftShader，不涉及真实扬声器。每组合只有一次最终观测，不报告P95。

排空判定要求当前generation已收到`clip_end`、音源和待渲染队列为空、播放器停止且idle显示。它只证明已经观察到的片段排空；若模型稍后继续生成下一片段，不能据此判定完整LLM轮次已经结束。文字约束检查只忽略末尾标点，不是对生成语音的人工试听结论。

## 失败记录与回归

首次启动因连接按钮位于小窗口可视区域之外，点击未生效；尚未连接或注入音频。调整为滚动到按钮后再真实点击。第一轮三条级联记录因测试错误要求`speech_started`而超时，实际协议为`interrupted`；三条端到端记录通过。原始失败分类保留，修正后以统一脚本重新运行最终六组合，没有把早期失败改成成功。

新增11项测试覆盖样本边界、奇数字节、发送缓冲上限、取消、等待中socket关闭、异步输入失败、清理等待、自然结束不能冒充打断，以及文本/手动打断污染。前端与评测共37项Node测试和1个idle断言脚本通过。独立审查核验六份真实轨迹、输入清理和代码摘要。

## 复现方式

1. 准备两份有权使用的16kHz单声道PCM16 WAV，记录文件/PCM SHA256；传给浏览器的base64应仅包含PCM数据，不包含WAV头。每份输入上限30秒。
2. 打开实际`/avatar`页面，在连接前通过浏览器自动化的脚本执行接口依次加载两个探针文件。选择后端和数字人、点击连接，等待`avatarDemo.metrics.connected`；保持物理麦克风关闭。
3. 在浏览器中运行以下调用；`firstPcmBase64`和`secondPcmBase64`由本地WAV解包后传入。端到端使用`speech_started`，级联使用`interrupted`。

```javascript
await voxaVoice.run(firstPcmBase64, secondPcmBase64, 'cascade-dinet', {
  resetReason: 'interrupted',
});
// 成功或失败后均保存状态；run 的 finally 会清理此测试连接。
JSON.stringify({
  round: voxaVoice.last,
  inputs: voxaVoice.inputs,
  resets: voxaVoice.resets,
  trace: voxaProbe.snapshot(),
});
```

每组合使用新页面串行运行，保存探针代码摘要与失败记录。导出结果时去掉sessionId；不导出原始音频、服务地址或私有配置。不要在用户正在使用的会话中安装探针。

完整动态口型质量、人工听写/试听、物理采集和出声计时仍待完成。DINet消费节奏优化仍属于待验证候选，本记录没有改变第一阶段的整体状态。
