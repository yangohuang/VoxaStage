# 数字人与多模态演示路线

目标是在约两分钟内展示可验证的系统行为与一项受控实验。模型环境按各worker文档部署；本次运行完成后已恢复原语音服务，默认页面没有自动开启视觉。

## 准备

使用[部署说明](DEPLOYMENT.md)配置三种数字人服务及idle素材。MiniCPM显式添加`--vision --visual-grounding general`，同时提供男女音色参考；健康接口应报告`image_input:true`和`visual_grounding_policy:"general"`。应用的`PIPECAT_MINICPM_URL`指向该worker，在`/avatar`选择MiniCPM后连接。具体启动参数见[worker说明](../omni-server/README.md)。

准备两张相同构图的图：左侧圆形先红后绿，右侧均为蓝色方形。下面的结果来自合成输入及真实模型测试，现场真人语音的识别与听感需现场确认。

## 展示步骤

1. **无图问题**：直接问“图中左边是什么颜色和形状？”展示模型说明缺少图片。说明原提示在本探针8次都猜测，两个提示变体均为0/8；不要说已经解决通用幻觉。
2. **当前画面**：上传红圆图，等“画面已确认”后用文字提问。指出画面先确认，再绑定下一轮；上传后不会改变已经开始的回答。
3. **联合输入**：上传绿圆图，再说同一句问题。真实现场可用麦克风；已有自动化记录使用合成PCM经浏览器WebSocket和真实VAD，不能将它表述为真人麦克风验收。
4. **历史与裁剪**：重新上传红圆图，询问与上一张的变化。展示绿色变红色的回答及“最多保留最近两张画面”提示。
5. **打断**：要求详细描述，播放中点击打断，再换图提问。说明旧音源与画面停止，未播完回答作为中断标记进入历史；不声称所有已提交的GPU计算可强行取消。
6. **驱动切换**：断开后换DINet/FlashHead/StreamingTalker，展示2D、3D以及男女声路由。等待及断开后的idle循环属于应用媒体状态管理。
