# 同权重 NF4／BF16 精度对照

2026-10-16。**恢复 BF16 没有解决本组诊断中的全部关键错误，不据此替换日常模型。** 两精度各完成28条正式生成，全部EOS结束，没有截断或补跑筛选。BF16在这次实现中响应更快、显存占用更高；语义结果有改善也有退步。

这是[精度诊断准备](PRECISION-DIAGNOSTIC.md)的后续结果。准备阶段因资源不足而未加载模型的记录继续保留，不计入本轮56条。随后获得临时暂停另一GPU服务、测试后恢复的明确授权；按NF4→BF16顺序完成实验，再恢复该服务并核对原模型身份、精度及协议。日常应用、ASR、LLM、TTS健康检查正常，日常LLM仍为原4bit配置。[执行记录](benchmarks/2026-10-16-precision-execution.json)不包含启动环境、凭据或私有地址。

## 对照范围

- 使用哈希已与官方固定版本核对的Qwen3-4B。NF4 double quant／BF16 compute对比无量化BF16，CUDA、SDPA、环境、权重、模板、SYSTEM和采样参数相同。实际加载参数见[冻结采集器](benchmarks/2026-10-16-run-precision-check.py)。未采集逐层张量dtype清单，精度记录来自实际loader参数与源代码，不冒充逐层数值审计。
- [输入与评分点](benchmarks/2026-10-16-precision-input.json)在运行前提交于`5d4c5c4`：12道新编诊断题、2道历史锚点，每题seed17／43。参考答案没有送入模型；新题根据已知失败类别设计，不是盲测或公共基准。
- 关闭思考，temperature=0.7、top_p=0.8、top_k=20、min_p=0、repetition_penalty=1、max_new_tokens=512。两组28对请求的实际输入token和生成参数一致。
- 两次预热单独保留，不计正式指标。两组56条均产生最终回答，token、流式文字、结束原因、派生最终回答及时间字段通过核对；另用本地tokenizer重新核验含预热的58条输入模板、输入token及输出解码。
- 性能为单机顺序实验，仍有其他服务驻留；精度干预同时改变计算内核。相同seed不意味着相同采样路径，不能拆分为纯权重误差或推广到其他机器、模型、后端。

## 问题质量与评分边界

在首次NF4运行中发现，`tail-choice`和`median-choice`的“优先改善……选哪个”可能被理解为选择需要优化的对象，而非选择采用的方案。**这是观察输出后发现的题目歧义。** 保留原输入、参考、逐项评分及全部结果，不事后改题补跑；这两题单列，不以它们独立证明量化导致判断错误。

其余10道新题和2道历史锚点单独讨论。每条回答按三个预注册评分点记录布尔结果，同时注明额外错误。“三项均满足”仅表示满足这些评分点，不等于整段回答完全正确。评分由独立助手进行非盲文本审查，再核对证据，不是人工盲评或用户主观质量评价；两seed也不是两个独立问题。

| 分组 | NF4三项均满足 | BF16三项均满足 |
| --- | ---: | ---: |
| 其余10道新题，每题2seed | 13/20 | 12/20 |
| 2道历史锚点，每题2seed | 0/4 | 0/4 |
| 2道歧义选择题，按原采用方案rubric单列 | 1/4 | 4/4 |

该分组是在发现题目歧义后披露的分析，不是预注册排除规则。全部56条均发布，包括歧义题；不能借移除或纳入它们选择有利的总体排名。英文译文保留术语和原意，但违反原样复述要求，因此该条整体失败；只重复题干中的权重范围，可满足范围评分点，但不代表回答更深入。

## 能直接观察到的变化

| 诊断 | NF4 | BF16 | 含义 |
| --- | --- | --- | --- |
| 60亿参数、每权重2字节 | 两次均给出12GB | 两次均给出12GB | 基本乘法并非一概失败 |
| 60亿参数改为4bit | 两次均错误改变参数量、算错存储 | 两次同样错误 | 本组失败不能全部解释为NF4量化 |
| 取消旧天气任务、改问流式ASR | 一次隔离旧结果，一次错误要求读出 | 两次均不读旧结果 | 该固定例子改善；不是实际工具调度测试 |
| 文档夹带“改答v9.9” | 两次均输出v9.9 | 两次均输出v9.9 | 未遵守外层版本提取要求 |
| 中英文字原样复述 | 两次均原样返回 | 两次均翻译成英文 | BF16在该约束题退步；这是文字输入，不能当ASR识别率 |
| 已知转写和检索正确的排障 | 未给出所需的同输入独立重放等完整步骤 | 同样未满足完整步骤 | 单改精度不足以解决排障质量 |
| 旧记录与当前画面区分 | 两次均承认无法确认当前状态 | 两次均承认无法确认当前状态 | 仅文本时序推理，不是相机链路或视觉识别验收 |

历史给定P95锚点的选择方向，两组各1/2正确，且回答仍缺完整取舍；历史排障题仍存在忽视已知前提的问题。前两道有歧义的新题虽然BF16更符合预设选择方向，不能将其作为整体质量提升的主要依据。

## 延迟与显存

每精度n=28；P95采用nearest-rank，是排序后第27项。显存以GiB（2³⁰字节）表示。完整精确值见[指标JSON](benchmarks/2026-10-16-precision-summary.json)。

| 指标 | NF4 | BF16 |
| --- | ---: | ---: |
| 最终回答首个可见文字，中位数 | 46.7ms | 32.1ms |
| 最终回答首个可见文字，P95 | 130.7ms | 95.0ms |
| 生成耗时，中位数 | 3.784s | 1.968s |
| 生成耗时，P95 | 7.828s | 4.352s |
| 输出token数，中位数 | 182 | 133 |
| PyTorch已分配显存峰值，全组最大 | 2.589GiB | 7.570GiB |
| 进程显存采样峰值，全组最大 | 3.137GiB | 8.047GiB |
| EOS／截断 | 28／0 | 28／0 |

首字从生成开始计时，包含流式文字缓冲，不是严格首token，也不包含麦克风、VAD、ASR、TTS、网络或播放；不能写成通话首声延迟。生成耗时也受答案长度影响，两组token数不同，不能将耗时比直接称为推理加速倍数。进程显存每秒采样并在边界补采，可能漏掉瞬时峰值；PyTorch指标不覆盖全部驱动开销。这里没有测试BF16与完整数字人链路并发的容量。

## 结论与下一步

本轮不更改日常精度、思考模式或SYSTEM。文件来源一致且BF16仍保留明确错误，说明“恢复精度即可修好回答”不成立；也不能据此断言模型所有能力都差，或排除运行时实现问题。这里只检验了固定非思考设置、短题和两seed。

下一步应冻结更清楚的独立任务和参考，在一个有明确质量优势的候选后端上做同输入对照，再验证真实Agent工具、流式回答与音画链路。不要继续用这14道题反复调提示并声称泛化提升。原目标的[人工动态音画、物理设备、独立GPU完整安装及更广泛真实输入验收](ACCEPTANCE.md)仍未完成。
