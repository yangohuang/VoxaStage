# MiniCPM-o 实测记录

日期：2026-09-18。模型 `openbmb/MiniCPM-o-4_5-awq`，固定版本
`a3073852f52e4beec3f278d1f6616d40c26fe343`。

## 部署与范围

用户明确授权后，将 worker 部署到 模型主机 的任务目录，使用原 MiniCPM 环境与缓存权重。
等待既有实验自然结束后加载模型，没有终止其他实验。原端口被占用，改为回环 18211，
通过 SSH 转发供 Pipecat 访问。模型报告已分配显存 12200 MiB。
当前为任务进程与 SSH 转发，没有安装开机启动服务。

Pipecat `/avatar` 可独立选择对话后端与三种数字人。级联仍为默认；MiniCPM 分支直接处理
16k 原始语音，输出24k音频，绕过外部 ASR、LLM、TTS。使用 VAD 分轮和合作式取消，
不声称已实现原生全双工。原纯语音 WebRTC `/` 入口保持级联。

## 真实模型

以下是一次测试中的实际结果，不代表延迟分位数或质量基准。计时从 HTTP 请求开始，
语音输入已预先上传为单次请求，不含用户说话时长。

| 输入 | 模型文字回复 | 首音频 / 总时间 |
| --- | --- | --- |
| 记住我的暗号是蓝鲸，请简短确认。 | 已记住暗号为蓝鲸。 | 2.424 / 2.569秒（首次请求） |
| 我的暗号是什么？（含上一轮历史） | 你的暗号是蓝鲸。 | 0.727 / 0.737秒 |
| 原始语音：请用一句话解释什么是实时语音交互。 | 实时语音交互是指用户通过语音与系统即时交流，系统即时响应。 | 0.923 / 1.969秒 |

三条回复均有真实24k PCM输出，分别为57600、43200、146880采样。
音频和结果保存在本地忽略的 `artifacts/omni-model/`，不随源码分发。
多轮历史需显式处理流式 API 的 assistant 角色边界及每轮音频状态重置，已加入回归测试。
补测原始语音历史后追问“我刚才用语音问了什么？”，模型回答“您刚才问的是：请用一句话解释什么是实时语音交互？”，输出116160采样，确认音频历史未被文本转写替代。

## 数字人组合与打断

通过真实 WebSocket 管线发送文字，在首媒体后打断，再发新问题；三组均完成新回答，
音频总采样数匹配，旧代媒体不越过 reset，会话断开后名额释放。

| 组合 | 首次媒体 | 第二次媒体（相对最初请求） | 恢复回答采样数 |
| --- | --- | --- | --- |
| MiniCPM＋DINet | 0.921秒 | 2.039秒 | 18240 |
| MiniCPM＋FlashHead | 1.184秒 | 2.168秒 | 24000 |
| MiniCPM＋StreamingTalker | 0.932秒 | 1.726秒 | 20160 |

第二次媒体的时间包含第一轮耗时，不能当成单独的恢复延迟。
完整结果：本地 `artifacts/omni-{provider}-interrupt.json`。

原语音另经 Pipecat VAD＋MiniCPM＋DINet 测试，第二次播放测试输入自动触发打断并恢复。
首媒体分别在测试开始后5.190秒与10.595秒到达（包含3.755秒输入语音、发送间隔及VAD等待），
恢复回答208320采样。见本地 `artifacts/omni-dinet-voice-interrupt.json`。

## 浏览器

独立 Chrome 测试会话选择 MiniCPM＋DINet，真实点击连接解锁 WebAudio。
第一轮“记住我的暗号是蓝鲸”回答“暗号已记，蓝鲸。”；播放完成后追问，回答“蓝鲸。”。
两轮累计渲染80帧、安排76800音频采样，结束时 playing=false、pendingFrames=0、
scheduledSources=0，页面无错误提示；连接期间模型选择锁定，测试后主动断开。
记录：本地 `artifacts/omni-browser-result.txt`。此项不代表物理扬声器测量。

## 限制

这些测试证明真实模型、媒体协议及打断恢复可用，不证明物理扬声器试听效果、口型质量、
长历史性能或长时间稳定性。历史最多六轮及60秒语音，截断有提示；被打断的回复只保留
中断标记。完成播放后保留回复文字，原始用户语音仍以音频形式传入下一轮。
