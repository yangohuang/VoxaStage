# MiniCPM 中英文术语与音频尾块修复

2026-10-10 用户反馈：DINet 男性角色使用 MiniCPM 时声音不匹配，中英混合输入容易误解。角色选择确实传递了 `male`，但端到端与级联使用的男声参考不同。本机已统一使用级联的男声参考；音色是否符合预期仍需真人试听，不把参考文件一致视为音色验收。

## 固定音频对照

MiniCPM 直接处理语音，没有调用级联 ASR。使用同一模型版本、男声参考和五段固定合成音频，比较原系统提示与可选 `--speech-context`。每段运行三个 seed，每对条件使用相同 seed，并轮换先后顺序，共 30 次。推理使用相同的流式参数；记录完整回复和音频时长。该实验直接调用 engine，不经过 HTTP 的 30 秒输出限制。

| 合成输入 | 原提示 | 术语提示 |
| --- | --- | --- |
| 介绍一下语音 agent 技术 | 3/3 回答语音 agent | 3/3 回答语音 agent |
| 请解释一下 VAD 和 ASR 的区别 | 0/3 命中目标概念，回答 VIT/ISR、VAT/SR 或 V8/SR | 3/3 回答语音活动检测与自动语音识别 |
| 我们用 WebRTC 传输语音，用 Python 处理模型输出 | 3 次全部因极短尾块报错 | 3 次全部因极短尾块报错 |
| 请用一句话解释 VAT 增值税 | 1/3 解释 VAT，2/3 误解成“未提增值税” | 2/3 解释 VAT，1/3 仍误解成“未提增值税” |
| 英语单词 white 是什么意思？请简短回答 | 3/3 回答白色 | 3/3 回答白色 |

表中只判断回复是否涉及目标概念，不评价整段知识准确性；例如“VAD 判断有没有声音”仍不够严谨。VAT/white 中未观察到被强行改写为技术术语，但 VAT 仍有误解。固定合成输入没有人工逐字校对，重复 seed 也不是独立真实用户，不能据此计算真人 CER 或宣称通用中英混合问题已经解决。

[完整对照记录](benchmarks/2026-10-10-minicpm-speech-context.json)包含输入哈希、seed、全部回复、错误和时长。模型固定在 `a3073852f52e4beec3f278d1f6616d40c26fe343`，男声参考 SHA256 为 `f725553f437e9b6f71b427b32e8bdeda95a6024452b75775a3409f24e13ea89c`。音频与本机服务配置不放入公开仓库。

## 输入边界修复

WebRTC/Python 样本略长于四秒，按一秒分块后尾块不足 125ms，触发模型音频特征池化的零长度错误。现在只对不足 2000 个采样点的尾块补静音到 125ms，保留所有原始采样，不修改此前完整分块，也不重复附图。新增测试覆盖极短整段、边界值及多秒短尾块；22 项 worker 测试通过。上述 30 次对照在补齐及短回复修复前完成，原始失败全部保留。

## 使用与限制

部署者显式配置[术语提示](../omni-server/README.md#中英文术语提示)，默认关闭，最多 1024 字符；删除参数只移除领域提示。领域词不能替代真实语音，提示要求听不清时确认。参考音色、视觉策略和流式协议保持独立。

另有既有输出上限问题：原提示 4/15、术语提示 2/15 的完整音频超过 30 秒；HTTP 服务会终止这些回复并返回错误。因此概念理解正确不等于整轮通话成功，本次保留该上限，并将全局默认回复从通常180字调整为尽量60字、一到两句，生成token预算从256降至128；关闭领域提示不会撤销这项变化，短回复提示也不保证任何输入都低于30秒。用户当前优先可用的链路仍是 Qwen 级联，端到端链路保留用于后续真实中英混合语音验证。

## 最终服务检查

第一次候选上线时，短尾块已能生成 WebRTC/Python 回复，但触发 30 秒上限；部署门槛拒绝该版本并自动恢复原服务，随后确认 ready。失败没有算作通过。

加入短回复策略后，原短尾音频的上线门槛请求正常结束（5.2 秒音频），候选源码哈希与当前文件一致。随后 9 次真实 HTTP 请求全部返回 `done`：5 段固定语音、男→女→男三次音色请求、1 张红色合成图。最终 VAD/ASR 回答目标概念，WebRTC/Python 输入正常回复，VAT/white 对照未偏向技术术语；9 条音频最长14.08秒。音频首块在完整请求结束前到达，流式输出保留。

[最终 HTTP 记录](benchmarks/2026-10-10-minicpm-speech-context-http.json)独立于30次成对实验：最终版本同时包含领域提示、尾块补齐和短回复策略，不能用该9次检查单独归因某一项改动。它没有验证真人口音、噪声、主观男女声或物理麦克风，也没有重新验收三种数字人画面。
