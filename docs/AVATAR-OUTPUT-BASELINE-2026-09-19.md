# 输出与浏览器初始记录 · 2026-09-19

状态：第一阶段新增受控输出捕获和浏览器回归；完整生成质量验收仍未完成。

## 输出覆盖

五类共15个探针：中文、英文、中英混合各3条，三种静音长度，以及三条从中文音频拼接的停顿样本。三驱动共45次完整输出通过，保存3644帧及逐样本一致的配对PCM。文件、输入哈希、代码指纹、部署标签与逐帧索引保留在本地忽略目录；源码库只包含无服务地址的数值记录。

这批输入全部为合成/生成探针，提示文本未经人工听写复核。停顿样本复用了中文片段，不是15条独立真人录音。三个固定人物分别记录，不以同一声音与人物匹配度作跨模型排名。权重摘要及部分部署版本尚未核实，当前可复现流程，不能承诺在另一部署复现精确数值。

对两种2D驱动的3秒静音样本第0、37、74帧进行了自动静态抽查：FlashHead三帧中的嘴部形态相近，DINet三帧中嘴唇闭合或近似闭合，均有细小姿态变化。这不是整段动态观看、人工试听、音素口型准确性或身份评分；3D尚未进行渲染质量复核。所有感知质量字段仍为未测。

## 浏览器六种组合

同一条合成中文WAV，经Chrome假麦克风采集，前后附静音。专用headless Chrome 148.0.7778.178，ANGLE SwiftShader；真实点击连接解锁AudioContext，未绕过自动播放规则。三驱动共享RTX4090并预加载，按顺序运行；没有并行基准请求。每种组合只有一次最终观测，不报告稳定P50/P95，也不据此排名模型。

“活跃包结束”是最后一个RMS大于0.004的发送包，不能等同于精确语音样本结束。“首声”是AudioContext安排的起点，不是物理扬声器出声。按钮打断后源数归零、旧帧在250ms观察窗内停止、短文本可恢复播放；这不等于语音触发打断已经测量。当前浏览器核心播放源码与工作分支一致，指纹见记录。

初始脚本曾将DINet流中的短暂空队列误判为恢复完成，两条测试因idle条件失败。这两条失败没有删除；补充了“匹配generation的clip_end、队列排空且idle播放”的条件和回归测试，随后六种组合重跑通过。此处修复的是测试判定，未修改在线播放器。

## 已发现的优化候选

Qwen级联 + DINet的短文本恢复请求只有一个clip，26个已安排音源中发现两处大于1ms的调度空隙，分别为186.7ms和37.3ms，合计224.0ms。计算式为相邻音源的`audioStart`减去前一音源的`audioStart + duration`，使用同一个AudioContext时钟。其他五条短恢复请求未观察到大于1ms的空隙。

这证明本次调度时间线上存在空隙；尚不能归因于模型、网络、解码或浏览器事件循环，也不能直接推断物理听感。下一步固定恢复PCM并重复运行，逐层关联媒体接收、JPEG解码和安排起点；比较缓冲策略时同时报告首声代价与空隙减少，不能只增加预缓冲后宣称全面更快。
