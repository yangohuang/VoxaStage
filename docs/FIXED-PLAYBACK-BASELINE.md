# 固定PCM播放基线 · 2026-09-19

独立评测页复用生产`AvatarPlayer`及2D/3D渲染器，将固定PCM直接输入真实数字人适配器。这样控制ASR、回答内容和TTS变化，用于复现上一轮DINet的音频调度空隙；没有修改在线播放策略。

## 复现入口

```bash
.venv/bin/python avatar_playback_lab.py \
  --manifest artifacts/quality-inputs/cases.json \
  --config runtime/avatar-config.json --port 18424
```

在本机浏览器打开`http://127.0.0.1:18424`，选择驱动和样本，真实点击“播放并记录”解锁音频。部署在远程机器时使用本地端口转发，保留127.0.0.1访问方式；该工具只用于本地评测，不是公开多用户服务。后端不接受客户端提供的文件路径或服务地址，同一时刻只允许一个模型请求，断开或超时会清理流。

重复实验可在首次点击后从DevTools调用`await lab.run('dinet','zh-00')`，保存`lab.last`。每轮包含输入哈希、代码指纹和以下事件：

- `received`：浏览器收到媒体的performance时刻，以及独立的服务端适配器相对时间。
- `decodes`：JPEG解码调用起止；3D路径不使用JPEG，数组为空。
- `timelineReady`：有序提交播放器的时刻，可能包含等待前序解码的时间。
- `sources`：音源安排时的AudioContext起点与时长。相邻起点减去前一结束即调度空隙。
- `rendered`：调用渲染器返回后的performance时刻，是渲染提交，不是屏幕实际呈现测量。

只在同一时钟内相减。服务端和浏览器分别计算相邻间隔再观察模式，不把两者的绝对时间直接相减。每轮计数采用差值，失败轮次同样带输入/源码信息；解锁失败也恢复可重试状态。

## 当前证据

最终代码下12次请求通过：1次DINet预热、同一条2.432秒中文PCM在三驱动各3次、3D静音和停顿各1次。预热不进入下表。较早代码下的另外9次重复摘要也保留；当时只缺少自动更新页面选择框的显示修正，不与最终运行混算分位数。

| 驱动 | 三轮渲染帧数 | 每轮最大调度空隙（ms） | 每轮累计空隙（ms，阈值>1ms） |
| --- | --- | --- | --- |
| DINet | 61 / 61 / 61 | 122.7 / 202.7 / 138.7 | 208.0 / 256.0 / 229.3 |
| FlashHead | 61 / 61 / 61 | 0 / 0 / 0 | 0 / 0 / 0 |
| StreamingTalker | 73 / 73 / 73 | 0 / 0 / 0 | 0 / 0 / 0 |

DINet三轮最大空隙均对应第19→20帧：适配器出口间隔约267.1 / 304.8 / 260.0ms，浏览器接收间隔约267.3 / 304.6 / 260.0ms；对应JPEG解码约2.1 / 1.9 / 2.5ms。这支持“该样本的主要供帧间隔在适配器出口已出现”，不支持将问题归因于浏览器JPEG解码。它仍不能区分原生DINet服务、适配器编码、输入节奏等上游因素。

测试环境为预加载、共享RTX4090模型服务与独立headless Chrome148/ANGLE SwiftShader，串行请求。只有一条语音输入和三次正式重复，不能作为三模型速度/质量排名，也不能代表生产P95。空隙是安排时间线的事实，未测物理扬声器。

3D静音90帧、停顿176帧均完成播放。另一次独立可视检查抽取第15、87、120次渲染回调：网格正立且完整，嘴形有细微变化。这只是几个时点的自动视觉检查；没有由这些截图推断逐音素准确性、主观自然度或听感。本轮不再将“3D未实际渲染”列为缺项，但完整动态质量与人工核对仍待补。

## 验证与下一步

121项应用/评测Python、27项浏览器与播放器测试通过；新增7项服务测试覆盖同源/Host、错误隔离、并发、取消、超时，5项浏览器模拟测试覆盖并发启动、失败保留、计数隔离和渲染时间边界。既有worker未改动。

下一步在固定输入下继续拆解DINet原生接收、图像编码和输入节奏，再选择有因果证据的优化变量；优化需同时报告首声代价、调度空隙、输出完整性及资源代价。完整质量基线仍未验收。
