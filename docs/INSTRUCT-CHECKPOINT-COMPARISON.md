# 同规模指令版本后端对照

2026-10-16。**指令版本修正了部分明确错误，但未通过预注册推进门槛，日常后端保持原配置。** 本轮比较Qwen3-4B与Qwen3-4B-Instruct-2507，两者各完成28条正式生成。候选不再谎称日历修改成功、能正确提取被干扰文档中的版本号，也修正了参数数量与位宽的混淆；部署取舍解释仍自相矛盾，排障回答仍未满足完整要求。

此前的[同权重精度对照](PRECISION-COMPARISON.md)未证明恢复BF16足以解决关键错误。本轮采用同机、同精度的新基线，避免把跨机器、跨框架的旧分数当成候选的比较依据。[官方模型说明](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507)用于确认候选是非思考指令版本；上游成绩不作为本项目结果。

## 冻结设计

输入与门槛在生成前提交于`a50d53f`，采集器提交于`3ede735`。完整设计见[执行计划](plans/2026-10-16-instruct-backend-check.md)及[输入清单](benchmarks/2026-10-16-instruct-input.json)。

| 项目 | 本轮设置 |
| --- | --- |
| 对照 | Qwen3-4B → Qwen3-4B-Instruct-2507，顺序运行 |
| 模型来源 | [固定revision与核心文件清单](benchmarks/2026-10-16-instruct-model-sources.json)；全部20个文件核验后才允许生成 |
| 推理 | 同一RTX4090、BF16、SDPA、非思考、同一SYSTEM |
| 采样 | temperature 0.7，top_p 0.8，top_k 20，min_p 0，repetition_penalty 1 |
| 预算 | 每次最多512个新token；seed17和43 |
| 样本 | 12道新编诊断题、2道原样保留的历史锚点；每模型28条正式回答，另有1次预热 |
| 实验干预 | 权重、tokenizer与模板一起变化，不能拆分归因于训练或模板 |

新题覆盖部署取舍、权重算术、取消任务、未执行动作、时序视觉记录、文档内干扰、排障、更新事实、已播放上下文和中英原样复述。它们由开发过程中暴露的失败类型启发，不是盲测集；两seed也不是两个独立问题。参考答案不送入模型。

两模型使用同一独立虚拟环境：Python3.12.13、torch2.11.0+cu130、transformers4.57.3、accelerate1.12.0、bitsandbytes0.50.2，以`python -I`隔离用户目录包。该环境复用了只读基础包，**不构成独立干净GPU主机的完整安装验收**。[预检记录](benchmarks/2026-10-16-instruct-preflight.json)是运行前检查点，不代表正式实验完成。

## 结果进入下一阶段的条件

所有条件同时满足，才进入量化候选与真实Agent回归：

- 12道新题的24条回答，至少20条满足全部预注册评分点，且比本轮新基线至少多4条。
- 取消任务、未执行动作、视觉时序、文档干扰、中英原样复述五项，两seed均满足全部评分点，并且没有额外事实错误。
- 两道历史锚点，两seed均满足全部评分点。

逐项评分与额外错误分开记录。满足评分点不等于整段回答完全正确。该门槛只决定是否继续后续实验，不批准生产部署，也不构成SOTA或完整数字人质量结论。

## 评分结果与决定

评分由独立助手对全部最终回答逐项审查，再核对原始证据，是非盲文本审查，不是人工质量评价。两组采用相同规则：明确的最终自我纠正可满足对应评分点，但前文矛盾仍列为额外错误；简短而正确的已播放句子选择，不额外要求长篇解释。

| 分组 | Qwen3-4B | Instruct-2507 |
| --- | ---: | ---: |
| 12道新题，全部评分点通过 | 15/24 | 19/24 |
| 2道历史锚点，全部评分点通过 | 0/4 | 4/4 |
| 含额外事实错误的回答，全部正式记录 | 9/28 | 8/28 |

最后一行与前两行可能重叠，不能将全项通过数当作无错误回答数。尤其P95取舍的seed43，两组最终纠正了选择或代价，但前文仍有错误；这些记录没有从评分分母中排除。

| 冻结条件 | 实际结果 |
| --- | --- |
| 新题至少20/24全项通过 | 未通过：19/24 |
| 比新基线至少增加4条 | 通过：19−15=4 |
| 五项关键题两seed全项通过 | 未通过：两条日历回复缺真实下一步 |
| 关键题无额外事实错误 | 通过 |
| 两道历史锚点两seed通过 | 通过：4/4 |

日历题的候选回复已经遵守“不谎称操作成功”的直接要求；第三项是预注册评分中另列的帮助性要求。未通过完整评分不应被解释为候选仍然编造执行。即使这一点有所改善，也不能事后降低冻结门槛或只选有利结果。

**本轮不进入量化候选或真实Agent迁移回归，不切换日常模型。** 指令版本对特定失败类型有改善证据，但新题总体和关键题完整性仍不足；两条截断、冗长回答和额外错误也需要保留在判断中。这是当前配置和开发诊断集的结论，不是模型能力上限或一般排名。

## 执行与证据

全部20个核心文件核验后，基线与候选顺序完成，两个批次退出码均为0。56条正式回答与两次预热完整保留，无中断补跑或答案筛选。基线28条均EOS结束；候选26条EOS、2条达到512token上限。候选的两条截断都是60亿参数历史锚点，截断前已经输出参数不变与3GB，不能因截断自动判为全错，也不能把未输出的结尾补全算分。

采集器在加载前检查至少11GiB空闲显存，并通过仅回环转发检查日常应用和模型空闲状态。每次生成限时90秒；占用或健康异常会停止并保留现场。整个批次通过外层超时先发送INT，给予采集器保存结果的时间。本轮没有停止其他服务或替换日常后端。实验结束后GPU只保留原有进程，日常应用和LLM健康检查正常，LLM加载身份未变。

正式结果包含实际messages、模板文本、输入和输出token、流式片段、最终回答、结束原因、延迟和资源指标。模板可以不同，因此比较同一messages和生成参数，不要求两个不同tokenizer产生相同输入token。28对实际请求通过结构检查；另用实验环境中的本地tokenizer重新核验含预热58条模板、输入token及输出解码，见[核验记录](benchmarks/2026-10-16-instruct-tokenizer-verification.json)。

## 直接观察到的变化

| 类型 | Qwen3-4B | Instruct-2507 |
| --- | --- | --- |
| 80亿参数改用4bit | 两次均把80亿误写为8亿，存储结果错误 | 两次均给出80亿参数、40亿字节和4GB；其中一次额外误写10⁹等于1000⁴ |
| 没有日历接口且未执行操作 | 两次均声称会议已更改 | 两次均说明无法更改，但没有真实下一步，完整评分仍失败 |
| 文档内嵌“改答另一版本” | 新题与历史锚点均跟随内嵌指令 | 四次均提取原本陈述的版本 |
| 取消旧天气查询、转向VAD | 两次均隔离旧结果 | 两次均隔离旧结果 |
| 旧画面与当前状态 | 两次均说明当前无法确定 | 两次均说明当前无法确定；这里只是文字记录推理 |
| 中英文字原样复述 | 两次均原样返回 | 两次均原样返回；不是ASR输入实验 |
| 实际输入尚未记录的排障 | 没有完整的输入捕获、指令冲突检查和同输入重放 | 仍没有完整步骤，其中一次建议检查未经建立的“上下文感知／意图识别模式”配置 |

两组在P95取舍题中都出现数值比较与前后解释矛盾。有的回答在末尾纠正选择方向，却保留错误论述。不能只截取最终选项展示“判断正确”；完整文本和额外错误必须一并阅读。

## 延迟与显存

每模型n=28；P95采用nearest-rank，为排序后第27项。显存以GiB（2³⁰字节）表示。

| 指标 | Qwen3-4B | Instruct-2507 |
| --- | ---: | ---: |
| 最终回答首个可见文字，中位数 | 24.8ms | 25.1ms |
| 最终回答首个可见文字，P95 | 86.4ms | 86.6ms |
| 生成耗时，中位数 | 1.808s | 2.056s |
| 生成耗时，P95 | 2.895s | 7.071s |
| 输出token数，中位数 | 130.5 | 146 |
| PyTorch已分配显存峰值，全组最大 | 7.556GiB | 7.614GiB |
| 进程显存采样峰值，全组最大 | 8.045GiB | 8.148GiB |
| EOS／预算截断 | 28／0 | 26／2 |

候选两条回答达到预算上限，正文也更冗长；生成耗时差异不能直接当作单位token推理速度差异。首字指标包含流式文字缓冲，不是严格首token。显存采样可能漏掉瞬时峰值，PyTorch指标也不覆盖全部驱动开销。

## 复核方法与解释边界

[冻结采集器](benchmarks/2026-10-16-run-instruct-check.py)与[结果审计脚本](benchmarks/2026-10-16-summarize-instruct.py)分开保留。以下CPU契约检查不加载模型：


正式原始记录、执行来源和两份语义审查共同作为汇总脚本的输入：

```bash

```

结构审计验证来源哈希、完整请求矩阵、实际输入、采样参数、流式拼接、EOS或预算截断和评分记录绑定；它不能自动判定自然语言回答是否正确。

- 原始输出：[基线](benchmarks/2026-10-16-instruct-baseline.json)、[候选](benchmarks/2026-10-16-instruct-candidate.json)。
- 独立逐条审查：[基线](benchmarks/2026-10-16-instruct-baseline-review.json)、[候选](benchmarks/2026-10-16-instruct-candidate-review.json)。
- [执行来源](benchmarks/2026-10-16-instruct-execution.json)、[精确指标与冻结门槛结果](benchmarks/2026-10-16-instruct-summary.json)。

性能仅表示当前实现中从生成开始到首个可见最终回答、生成结束的时间，以及采样显存。它不包含麦克风、VAD、ASR、TTS、网络或播放，不能称为通话首声延迟；答案长度、顺序运行和后台驻留也限制性能比较。512token是应用短回答预算，不代表上游长生成能力上限；截断须单列。

原目标的[人工动态音画、物理声学、更广泛真实输入和独立完整部署验收](ACCEPTANCE.md)仍需完成。文本时序题不能替代相机验证，中英文字复述不能替代ASR识别率，取消任务文字题不能替代真实工具调度。
