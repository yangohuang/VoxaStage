# 本地模型、输出预算与采样对照

2026-10-16。**未替换日常模型。** 两代本地4B模型在本次固定提示、NF4与非思考配置下，都没有解决已知的前提忽略和约束回答问题。增加输出预算没有改变任何一道贪心解码题的输出；采样也没有稳定修复关键错误。

## 预先固定的设计

输入与逐题 rubric 在运行前提交于 `15d4d88`，基于源码 `6f8e9c1b848a4a252e6af3678db94d80e1322cbd`。八道题包括三道历史复杂题，以及目标纠正、P50/P95取舍、证据不足、语义打断和视觉记录时序五道新增题。它们是开发用例，不是公开基准、独立盲测或八十个独立问题。

| 变量 | 配置 |
| --- | --- |
| 模型 | 本地 Qwen3-4B、Qwen3.5-4B，逐一独立进程加载 |
| 提示 | 同一份生产 `bot.SYSTEM`，无额外改写；不添加 Agent 工具提示或执行工具 |
| 量化 | NF4、double quant、BF16 compute、SDPA |
| 思考模式 | 两模型均 `enable_thinking=False` |
| 条件一 | greedy，最多256 token，seed17 |
| 条件二 | greedy，最多512 token，seed17 |
| 条件三 | sample，最多256 token，seed17/29/43；temperature0.7、top_p0.8、top_k20、min_p0、repetition_penalty1 |
| 总量 | 每模型8题×5次=40次，共80次正式生成，另各1次预热 |

采样参考[Qwen3官方非思考参数](https://huggingface.co/Qwen/Qwen3-4B)与[Qwen3.5官方通用非思考参数](https://huggingface.co/Qwen/Qwen3.5-4B)，未加入后者建议的 presence penalty，不宣称完整复刻官方最佳配置。固定短回复预算与本地量化配置，也不能代表上游模型能力上限。

按题目轮换条件顺序及采样seed顺序，两模型仍顺序执行。相同token上限跨tokenizer不等于相同字符预算。模型、tokenizer与chat template作为一个整体变化，不能将全部差异归因于单个架构或训练改进。

## 结果与部署决定

1. **80/80正式生成均以EOS结束，没有长度截断。** 两模型各八道题的greedy256／512输出token完全相同，共16/16对。就这批短题而言，提高最大输出预算没有收益；不能据此断言长任务也不受预算影响。
2. **已知识别正确的排障题仍失败。** 两模型每个条件都重新从ASR识别错误讲起，未完整检查实际模型输入、系统提示冲突和独立重放。共10条回答，不能因列出三步就算完成任务。
3. **24GB本地约束题仍未给出质量评测闭环。** 回答侧重压缩或替换模块，并多次把降低渲染负载、缩短上下文或流式输出等同于提高回答质量。两模型均未达到预设门槛。
4. **P95取舍出现明确方向错误。** 题目给定级联P95=1450ms、端到端P95=1100ms且用户重视长尾；Qwen3五次均选级联。Qwen3.5仅一个采样seed选端到端，但附加了没有测量支持的瓶颈归因。其greedy回答还将800−620误说为220ms。
5. **目标纠正可用，时序证据边界仍不足。** 两模型均保留新代号和新预算；但把12秒的最后画面直接当成13秒实时事实，没有表达记录之后状态可能变化。
6. **替换模型还带来回归。** 独立审查中，架构比较的错误定位取舍由Qwen3的5/5下降为Qwen3.5的2/5；后者在打断题中还出现“口头停一下不算实际操作”、旧结果恢复后继续输出等错误。

以上按逐题检查点与额外事实错误分别记录，不合并成一个可掩盖失败的总分。协议正常结束、rubric满足和完整事实正确也分别判断。独立文本审查是助手审查，不是真人盲评。

本次没有达到候选部署门槛，日常Qwen3服务未切换、未重启。不能据此宣布“Qwen3.5整体更差”或“模型本身不行”；当前应用提示、非思考策略、量化和小样本均限定了结论范围。下一步若继续质量实验，应单独控制推理模式或应用事实提示的影响，先证明关键题目改善，再验证工具、语音和数字人联动。

## 性能观察的边界

| 模型／条件 | 生成总耗时中位数 | 首个可见文本中位数 | 观察到的进程显存峰值 |
| --- | --- | --- | --- |
| Qwen3 greedy256 | 1.462s | 0.047s | 3222MiB |
| Qwen3 greedy512 | 1.474s | 0.050s | 3222MiB |
| Qwen3 sample256（三seed） | 1.417s | 0.052s | 3222MiB |
| Qwen3.5 greedy256 | 2.531s | 0.118s | 3644MiB |
| Qwen3.5 greedy512 | 2.518s | 0.116s | 3644MiB |
| Qwen3.5 sample256（三seed） | 2.342s | 0.117s | 3644MiB |

这是同一RTX4090上当前实现的本地生成观察，提示tokenization和模型加载不计入生成耗时，解码器缓冲后的可见文本不等于首token，更不等于物理首声。没有经过ASR、TTS、浏览器或数字人。不同回答长度影响总耗时，不能据此排列完整产品速度。

环境为torch2.11.0、transformers5.12.1、bitsandbytes0.50.2、accelerate1.14.0。Qwen3.5的 `is_fast_path_available=False`，使用Torch回退实现，不能把该耗时作为优化后架构能力的结论。日常模型与其他服务仍驻留显存，因此这里的候选进程显存也不是整套系统单卡部署占用。

进程显存在生成前后及约每1秒通过 `nvidia-smi` 采样，正式条目采样错误为0；它是观察峰值，可能漏过短暂峰值。原始数据另保留PyTorch allocated/reserved峰值，二者不混用。异常条目不据取消耗时计算吞吐，因为等待线程退出期间可能还有token到达。

## 采集修订、验证与复现

采集器首版已经完成Qwen3的40条及1次预热。随后审查指出：失败路径缺token、未预登记待执行请求、框架显存不等于进程显存。因此保留[首版代码](benchmarks/2026-10-16-run-model-decoding-pilot.py)和[首版结果](benchmarks/2026-10-16-model-decoding-qwen3-pilot.json)，修订采集器后重新运行两模型的全部80条。首版40条不混入正式统计；正式Qwen3文本与首版40条完全一致。全程实际记录120条非预热生成和3次预热，没有覆盖或隐去首版。

修订后在文件创建时登记40条pending，准入、tokenization、模型错误均落到对应条目；流式记录实际token，异常时统一保存已有输出、终止原因与测量字段。每题前及生成期间检查日常应用活跃会话，遇占用或健康异常停止实验，另有90秒生成时限。原始结果有模型文件SHA256、完整模板、实际输入／输出token和流式文本，支持检查截断与提示差异。

7项采集器测试通过，包括真正运行fake模型的失败注入：预热完成，正式第一条输出两个token后抛错，保留token、文本、耗时、显存及剩余39条pending。它验证记录契约，不验证真实模型语义。正式80条的矩阵、输入／代码哈希、token数量、流式拼接与最终decode一致性已检查；两个实验进程正常退出，日常服务健康且模型未改变。
