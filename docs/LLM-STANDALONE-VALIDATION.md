# 级联 LLM 独立环境、中文检索与服务恢复

2026-10-10。在现有 RTX4090 主机上重建 Qwen3-4B NF4 的独立 Python 环境，恢复已退出的本机文本生成服务。真实工具验证还发现并修复中文整句查询零命中、摘要偏离问题两个检索问题。没有更换模型、训练权重或量化算法。

## 独立环境与服务

原虚拟环境开启 `include-system-site-packages`，Torch 与 Transformers 来自共享 Conda。新环境使用 Python3.12.13，63包完整SHA256锁；版本逐项一致，全部发行包位于新环境，`uv pip check`、核心导入及CUDA小运算通过。

核心版本为 torch2.11.0、transformers5.12.1、bitsandbytes0.50.2、accelerate1.14.0；实际CUDA13.0，RTX4090、驱动595.71.05。仍复用已有基础解释器/标准库、系统、GPU驱动及本地模型；15个模型文件在临时推理前后摘要一致。这不是空白GPU主机安装，也未重新证明模型发布渠道。

安装和运行见[LLM后端说明](../llm-server/README.md)。新用户systemd服务以持久源码及独立环境恢复原本机端口，启动到ready为5.073秒，上线后通过应用`LocalBackend`完成一次真实回复，日志无ERROR/Traceback，检查时无自动重启。启用服务不等于已验证重启或登出恢复；本次没有触发真实服务回滚。原应用进程也已退出，本轮没有启动整套ASR/TTS/数字人页面，因此不宣称整站已恢复。

## 流式生成验证

临时worker阶段共21次模型生成请求：17次直接协议请求，以及计算、文档检索两个Agent回合引发的4次生成。17次包括1次预热、三类问题各3轮、1次长回复、3组客户端断流/恢复；18次完整接收，3次主动关闭客户端流。三次关闭前首文字时均观察到模型锁busy，随后锁释放并成功生成下一回复；没有内部停止事件计数，不能断言停止条件一定触发。

| 固定问题类别 | 正式次数 | 首文字／完整接收中位数（秒） |
| --- | ---: | ---: |
| 中文语音Agent原理 | 3 | 0.038 / 2.417 |
| 英文打断解释 | 3 | 0.060 / 0.993 |
| 中英混合流式推理 | 3 | 0.075 / 2.096 |

长回复199个非空文字事件，首文字0.040秒，完整接收5.277秒；首段时worker仍busy。这里是客户端NDJSON到达时刻，不是音频首声、物理麦克风延迟或单token时延，也没有同条件旧环境速度对照。重复只衡量这些固定问题的行为，不增加独立样本数。临时worker已退出，日志ERROR/Traceback均为0。

## 真实检索失败与限定修复

固定问题：**“请查阅项目文档：视觉图片的采集时间和上下文历史如何管理？简短回答。”**

1. **原始检索失败**：模型调用`search_project`时把“视觉图片的采集时间和上下文历史如何管理？”作为完整查询。旧工具仅按空格切词，文档中没有这一整句，返回空列表，模型回答未找到。首次21请求验证因此失败；另2请求专门复现并记录工具参数，原记录保留。
2. **只补中文匹配仍有问题**：增加双字匹配后，首项为`visual-interaction`，流程测试通过，但原摘要取文档开头。模型把`--vision`加载参数误当成采集时间机制。该协议通过记录保留，并明确不视为回答正确。
3. **最终修复**：仅在原精确/空格检索无命中时，使用中文相邻双字回退，至少两个不同双字命中；不拆英文标识符，保留原同分排序。回退摘要在最多600字符窗口中优先覆盖不同查询双字，再用剩余空间补前文。双指针时间与空间均随文长线性增长，文档目录、单文读取和总输出限制不变。

最终同一问题重复3轮，发生6次真实模型生成。三轮均出现`captured_at_ms`、两张图片/画面的上限，并且不含之前错误的`--vision`解释。原答复及自动检查保留。这是针对一条已观察失败的三个窄检查，不是全面语义评分；词语出现也不能排除其他错误，不能外推跨场景检索质量。此次最终检索复测与上表21请求是分开的阶段，源码摘要分别记录，不能混作同一版本的全量质量成绩。

新增8项工具回归覆盖中文整句、误匹配抑制、精确优先与同分排序、后部证据、窗口边界及穷举覆盖对照。发布版本完整应用277项测试通过。模型推理来自上游；本项目改动是部署约束、词法检索回退、摘要定位、服务恢复及可追溯验证，不是新模型能力或语义向量检索。
