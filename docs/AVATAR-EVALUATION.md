# 数字人评测：先固定口径，再讨论优化

[项目首页](../README.md) · [阶段路线](plans/2026-09-19-roadmap.md)

当前新增入口 `benchmark_avatar.py` 测量**数字人适配层**，复用三种真实模型的客户端，不改变线上服务。
它统一重复运行、失败计数、PCM / 时间戳校验和版本记录，为后续优化提供基线。
它不是完整端到端质量评测，不会把未测的指标填为零或通过。

初轮同版本实测见[2026-09-19 基线记录](AVATAR-BASELINE-2026-09-19.md)。

后续扩展见[固定PCM播放](FIXED-PLAYBACK-BASELINE.md)、[DINet供帧归因](DINET-DELIVERY-ATTRIBUTION.md)、[自动语音打断](VOICE-INTERRUPTION-BASELINE.md)和[浏览器采集边界](CAPTURE-TIMING-BASELINE.md)；各入口独立说明测量边界。

## 测量边界

| 层次 | 当前入口覆盖 | 不可据此推断 |
| --- | --- | --- |
| 输入 | 原 WAV SHA256、24k PCM SHA256、来源与转写核对状态 | 合成转写等于人工听写真值 |
| 适配链路 | 首配对媒体、完整耗时、接收间隔、帧序号、样本连续、逐样本原音频保持 | ASR / LLM / TTS 总耗时、裸模型生成速度 |
| 取消与恢复 | 首媒体后关闭生成器，再独立提交新请求验证恢复 | 物理扬声器已停止、上游 CUDA 运算立即停止 |
| 播放 | 本入口不启动浏览器 | 接收时刻等于出声时刻 |
| 生成质量 | 初始报告明确标为未测 | PTS 连续等于口型准确、身份一致或表情自然 |

所有时间为同一评测进程的单调时钟。计时起点在创建后端连接之前，包含连接、排队、模型、传输、解码校验及适配器已有的发送节奏控制。
`wall_audio_ratio = 完整请求耗时 / 输入音频时长`，不是模型 RTF；例如 2D 适配器有约1秒预送限制，长音频耗时受到该限制。

`burst` 尽快交付输入，`realtime` 按24k PCM的播放时长交付250ms分片；两种模式不能混算。预热同样记录，但不进入正式分位数。服务通常已预加载，因此预热也不代表模型冷启动。
每个 case 单独运行预热、正式轮次、可选首帧取消与恢复。正式统计按驱动、case、输入哈希与模式分组；失败计入分母，但不进入成功请求的延迟分位数。P50 / P95 为排序后线性插值，小样本只用于检查口径。

## 输入清单

JSON清单中的音频路径相对于清单文件。音频必须是8–48kHz、单声道PCM16，时长大于0且不超过30秒。
先为有权使用的文件计算SHA256，填入本地清单；不要把音频或本机路径提交到仓库。

```bash
sha256sum /path/to/voice.wav
```

以下为字段说明，`sha256` 要替换成命令得到的64位小写十六进制值后才能运行：

```json
{
  "version": 1,
  "cases": [
    {
      "id": "mixed-01",
      "wav": "voice.wav",
      "sha256": "替换为该WAV的实际SHA256",
      "category": "mixed",
      "source": "synthetic",
      "transcript": "介绍一下语音 agent 技术。",
      "transcript_reviewed": false
    }
  ]
}
```

`category` 可取 `zh/en/mixed/silence/pause/other`；`source` 为 `synthetic/recorded/generated_silence`。
`transcript_reviewed` 只表示转写经过人工逐句核对，不代表生成画面已评审。
输入清单最多100条；每条WAV在读取和重采样之前校验哈希及格式。所有模型得到同一份24k输入PCM，模型内部所需16k输入由各自适配器负责。

## 运行

在模型服务已经就绪的环境中执行；配置中只有对应 provider 的地址会被使用。
初始实验逐个驱动串行运行，以降低共享 GPU 上的竞争。单个输出目录不要用于两个并发评测进程。

```bash
.venv/bin/python benchmark_avatar.py \
  --manifest /path/to/cases.json \
  --config /path/to/avatar-config.json \
  --provider flashhead \
  --deployment-label 'FlashHead Lite pinned revision / RTX4090 / preloaded' \
  --warmup 1 --rounds 3 --mode burst --interrupt \
  --output artifacts/baseline/flashhead
```

另外两种驱动选择 `dinet` 或 `streamingtalker`；输出目录分别设置。`--deployment-label` 记录不含秘密的模型版本与硬件描述，不能把服务地址或密钥填进标签。环境变量与配置优先级沿用应用的 ProviderRegistry。

产物：

- `results.json`：参数、清单哈希、输入与PCM哈希、评测/适配代码指纹、依赖版本、每轮状态、分组统计及未测质量指标。
- `report.md`：便于阅读的汇总。

开跑先将状态写为running，单次完成后原子更新；失败最终返回非零退出码。配置、输入、模型错误均不保留旧成功状态。报告只记录异常类型，避免带出服务地址或私有错误响应；排查详情应在本地服务日志中进行。原始帧与音频不写入报告。

`--timeout` 限制接收阶段；正常结束和主动取消后的流清理独立执行，最多额外10秒，完整耗时包含清理。调用方在清理期间取消时仍等待清理任务完成。适配器自身在异常处理期间遭遇取消的所有竞争尚未完整覆盖，不能将本入口当作所有 GPU 清理路径的证明。

## 质量基线的下一步

后续输入、标注和浏览器时钟的具体规则见[质量评测协议](AVATAR-QUALITY-PROTOCOL.md)。

适配层验收通过后再扩展数据与测量，不将这一入口称为全部质量评测完成：

1. 建立中文、英文、中英混合、静音和停顿的分层样本，记录来源，人工复核真实语音转写。固定训练/调参样本与评估样本边界。
2. 保存限量、明确授权的输出用于盲评；分别标注口型偏移、闭口/张口错误、抖动、身份变化、头姿突变和idle切换。
3. 2D与3D独立分析。3D需说明观察视角、投影与参考条件，不能和真实人像直接共用身份评分。
4. 浏览器记录实际调度的播放起点和打断后停止时刻，服务端分阶段日志以轮次关联；跨进程时钟未经校准不直接相减。
5. 生成同步评估工具若使用另一个模型，需先校验其对语言、静音和无纹理3D画面的适用性；自动评分与人工判断分别报告。

这些是后续阶段门槛，当前报告中的 `measured: false` 必须保持到对应评测实际执行后。
