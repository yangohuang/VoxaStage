# 复杂回答质量基线：未通过的回复扩展实验

2026-10-10：用户报告新建会话后的文字/语音暗号记忆对照通过。本记录只将这一基础场景记为用户反馈通过，不外推通用中英混合识别、复杂推理或主观音画质量。

## 结论与当前服务

**没有上线本次扩展策略。** 当前继续运行 PR #15 的 MiniCPM 服务，保持端到端语音、术语提示、短尾修复和30秒输出上限。候选修改仅作为未采用的实验补丁归档，不是默认功能或推荐配置。

固定文字题证明部分回答问题在绕过语音理解后仍然存在。延长回复或增加“给出理由”的要求，没有证明能够稳定改善复杂回答。当前 Qwen3-4B 的同题参考也存在概念和前提处理问题，不能宣称简单切换后端即可解决。

## 方法

四道固定题覆盖：级联与端到端的三个比较维度、已知识别文本正确时的排障、24GB显卡且禁止云端和购买硬件时的质量改进、代号及预算纠正。每题的预设检查点保留在原始记录的 `cases[].rubric`，不按回答长短评分。

MiniCPM 使用同一权重、男声参考、领域词和视觉规则。每题运行三组seed，各组比较原策略（60字提示、128 token预算）与扩展策略（约100字、192 token、先结论和理由），轮换先后顺序，共24次直接引擎调用。输出仍为流式文字与音频，完整记录时长；直接引擎不会应用HTTP的30秒限制，超过限制的条目不能算生产接口成功。

| 检查 | 原策略 | 扩展策略 |
| --- | --- | --- |
| 信息纠正：蓝鲸、600元 | 3/3 正确 | 3/3 正确 |
| 完整音频超过30秒 | 3/12 | 2/12 |
| 引擎抛出异常 | 0/12 | 0/12 |
| 能否据此部署改善复杂回答 | 没有完成复杂质量验收 | 未达到上线门槛 |

超限次数下降不等于质量通过。原策略某次比较回答以未完成的“而 cascade”结束，虽然引擎没有报错；扩展策略仍有项目类型混淆和不充分利用题目前提的问题。

具体失败包括：

- 原策略在资源约束题中建议用 StreamingTalker 减轻显卡压力、降低 ASR 采样率来解决回答质量；这些建议没有建立与问题的有效联系。
- 扩展策略把 StreamingTalker 当作端到端语音助手，或声称数字人驱动能降低 ASR 处理负担、提升语言推理速度。
- 两种策略在“识别文字已经正确”的排障题中仍多次把重点放回识别错误，未充分检查系统提示、对话历史和模型输出。
- 延迟比较反复作架构层面的笼统判断，缺少模型、硬件、流式实现和测量条件；这不是可用的性能结论。

上述是对固定题的有限审查，不是盲评、通用模型排行榜或全部回复错误率。领域提示中包含项目名，可能影响这些输出；本轮没有拆分“模型能力、提示偏置、量化、解码策略”的因果贡献，不能直接断言全部来自权重能力不足。

## Qwen 参考

对现有 Qwen3-4B 提交同样四题、三个重复，共12次文字请求。该服务采用 `do_sample=False`、`enable_thinking=False`、256 token上限，重复回答一致；这相当于四道独立题，不是12个独立质量样本。

纠正题正确，但比较题仍将架构与延迟直接绑定；资源题把FP16精度转换笼统归为量化，且主要关注压缩与缓存，没有证明能改善回答质量。它是文字参考，系统提示、模型、tokenizer和解码策略均不同；未经过ASR/TTS，不对两种完整语音链路作公平排名或延迟排名。

## 下一阶段的门槛

优先比较候选本地回答模型与现有模型在同一批文字输入上的任务完成度，分别记录前提遵循、事实正确、约束遵循、输出截断与耗时；先确认回答层获益，再联动语音与数字人。增加没有项目名提示的控制条件，避免把提示偏置误判成全部模型能力问题。保持Qwen级联和MiniCPM端到端两条路径，不将强LLM级联包装成端到端模型。
