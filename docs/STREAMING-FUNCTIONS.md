# 流式对话、工具与会话恢复

VoxaStage 保留两条独立的对话链路。级联模式使用本地 ASR、Qwen 和 Index-TTS：语音按 VAD 分段识别，模型文字和合成音频增量输出。MiniCPM-o 模式直接接收语音或图像并生成语音，同样采用话轮边界；它不等同于原生全双工。数字人驱动独立选择 DINet、FlashHead 或 StreamingTalker。

## 工具任务

级联模式可由模型调用四种真实工具：

| 工具 | 输入与结果 |
| --- | --- |
| 项目文档检索 | 关键词 → 文档 ID 与片段 |
| 读取项目文档 | 白名单文档 ID → 有长度限制的正文 |
| 计算 | 限制语法的算术表达式 → 数值 |
| 服务状态 | 当前配置的 ASR、LLM、TTS → 经过筛选的状态 |

例如：“请使用计算工具计算 (137*29+81)/7”或“检索项目文档，说明支持哪些数字人驱动”。页面显示任务执行中、完成、失败或取消。工具返回后模型继续流式回答；工具协议不会被朗读。打断或提出新问题会使旧任务失效，迟到结果不会进入新轮次。

工具采用受限的文本调用协议，兼容当前本地模型，不依赖模型提供原生 function calling。最多三次工具迭代，默认单工具八秒、整轮六十秒；不提供任意命令、文件路径或网址执行。MiniCPM-o 当前保留端到端多模态推理，不支持这套工具调度。工具结果属于外部数据，不提升为系统指令。

## 播放确认与保存

浏览器在音频片段自然播放结束后发送确认，服务端再与实际已发送的采样数量核对。模型历史只保留确认播放的完整语句段；打断后的未听内容用明确标记替代。这里采用语句段级确认，没有宣称逐字口型或逐字播放时间戳。

页面支持新建、载入继续和删除本地对话。恢复时绑定原来的模型及角色，避免把不同后端的上下文混用。文字展示保留生成记录，并标明中断或未确认播放；模型上下文使用保守的播放记录。连接中的角色和模型选择锁定。

默认保存于 `runtime/conversations/`，可用 `PIPECAT_CONVERSATION_DIR` 指定保存根目录。目录内采用原子写入、版本检查和文件锁，最多二十个会话、单个四 MiB、总计六十四 MiB、四十轮。MiniCPM 上下文可能包含本地语音和图片，模型上下文最多六轮历史，额外限制累计输入音频及最近两张图片；点击删除会移除相应记录。运行数据不进入源码导出。

## 角色配置

部署者可在 `runtime/avatar-profiles.json` 配置角色 ID、名称、驱动、音色、idle 路径；完整例子见 [avatar-profiles.example.json](avatar-profiles.example.json)。不提供配置时兼容原来的三个驱动选择。

每个角色必须指向真实可用的服务和 `runtime/idle/` 下的对应视频。相同驱动的多个角色需要不同服务地址和 idle 资源，仅修改名称不能产生新的角色模型。可在部署配置中指定角色专用 `url`，浏览器只提交角色 ID。声音通过 `male` / `female` 映射到部署的声音样本，不代表人物本人声纹。

## 本轮边界

已纳入流式工具执行、本地会话和角色配置。多用户、公网认证、连续视频理解、原生全双工与主观音画质量评测单独安排。自动化检查和合成输入验证不替代真人麦克风、回声环境或口型质量验收。
