# MiniCPM-o 独立环境与持久服务验证

2026-10-10。在已有驱动和模型缓存的 RTX 4090 主机，新建 Python 3.10 虚拟环境、按完整 SHA256 锁安装119包，完成42次真实模型请求，并恢复原端到端入口。此结果覆盖依赖重建、协议与服务恢复，不等于空白 GPU 主机、语义质量或物理设备验收。

**`uv pip check`未通过：保留一项已知上游分发标签错误。** Decord0.6.0的官方文件名声明`py3-none`，内部WHEEL却标为`cp36-cp36m`；见[上游问题](https://github.com/dmlc/decord/issues/356)与[uv说明](https://github.com/astral-sh/uv/issues/15832)。没有篡改包元数据或把检查结果改写为成功。单项例外限定固定版本及WHEEL摘要，其余版本、依赖或平台问题不作豁免。

实际Decord通过ctypes加载共享库，未发现CPython扩展入口。四帧64×64合成视频的顺序读取、跳帧读取通过，RGB输出与系统FFmpeg逐像素一致；更换CPU TorchCodec后再次核验版本、依赖约束和相同视频输出。这说明本环境可执行该读取路径，不证明Decord全部格式或平台兼容。

基础解释器、标准库、系统FFmpeg、驱动及模型权重仍来自既有主机，没有重新下载或独立核验模型发布渠道。锁覆盖Python分发版本与摘要，不覆盖系统库、构建工具及编译产物。MiniCPM模型和AWQ能力来自上游，本轮贡献是环境约束、隔离、验证和部署整理。

## 真实请求与流式边界

两张既有合成图、一条合成语音问题，每个输入条件重复四轮，32次正式请求加1次预热；另有9次补充请求。共39次完整回复、3次主动取消；取消后均恢复，服务端最终requests=42、cancelled=3、failed=0。重复不增加独立样本数，未评定回答语义或音色主观质量。

| 正式输入条件 | 次数 | 首音频中位数／完整耗时中位数（秒） |
| --- | ---: | ---: |
| 原始语音问题，无图 | 8 | 0.872 / 2.296 |
| 图像与固定描述提示 | 8 | 0.847 / 1.493 |
| 图像与文字问题 | 8 | 0.845 / 1.159 |
| 图像与原始语音问题 | 8 | 0.864 / 1.095 |

补充请求包含男女声各1次、3组取消/恢复，以及1次较长回复。每次取消前后均核对服务端cancelled增长1，随后请求正常结束；不是仅关闭客户端就判定取消成功。取消只校验已收音频前缀，不计为完整回复。

较长回复收到14个PCM事件，首音频0.802秒、完整接收3.941秒；首块到达时worker仍busy。这里测量客户端媒体到达与模型锁状态，worker也会拆分单次模型输出，不能把事件数当作模型迭代次数。耗时不包含浏览器播放、麦克风、扬声器，也没有与旧环境进行同条件性能对照，不据此宣称加速。

本次使用VAD分轮端到端模式、视觉编码器及general约束；仍不宣称原生全双工、连续视频理解或新增级联工具能力。临时worker已清理，42次验证日志中ERROR和Traceback均为0。

## 服务恢复

现场发现原临时部署文件缺失、原worker未运行，因此将代码、环境和既有授权音色存放到持久用户数据目录，以新的用户systemd服务恢复既有端口。部署前检查无同名unit、端口空闲，并核验代码、锁和参考音色摘要。

服务启动到ready为9.092秒，随后女声真实请求通过，日志无ERROR/Traceback；检查通过后启用用户服务。再恢复原SSH本地转发，男声请求完整接收89280个采样、4个PCM事件。独立验证42次与上线后2次检查是不同范围，不混作同一批评测。

失败处理在启动前只清理本次文件；已尝试启动时先停止并确认退出，再删除本次unit。两项隔离故障探针验证部分文件及证据写入错误时仍能清理。本次实际上线未触发回退，不能称为真实服务回滚演练。用户服务启用不等于已验证机器重启、用户登出或跨主机自恢复。
