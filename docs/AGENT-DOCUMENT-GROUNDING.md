# 明确文档请求的执行与中英混合检索

2026-10-16。六条固定文字输入、四个开发阶段，共 24 轮 Agent 请求、28 次真实本地模型生成。最终版本修复了明确文档请求被跳过，以及英文标识符和中文主题相互排斥的问题；复杂回答质量仍未通过。这是部署代码的文字探针，不是完整语音或数字人验收。

## 起因与控制范围

[上一轮提示消融](PROMPT-PREMISE-ABLATION.md)没有使用日常应用的完整结构化事实提示，不能据此推断日常应用同样表现。本轮直接使用 `bot.SYSTEM`、`LocalBackend`、`AgentRuntime` 和 `ToolRegistry`，静态解析 SYSTEM，避免导入启动应用。六条问题和 rubric 在运行前提交，基线来自 `bba3d85ebb62cac1520325c7e2c2d8f7c7925bbf`，输入提交为 `0d9c002`。

模型为现有本地 Qwen3-4B、4bit，生成预算 256 token。四阶段模型健康信息一致，SYSTEM、后端和受限文档目录的内容哈希一致；代码干预只涉及 `agent_runtime.py` 与 `agent_tools.py`。每题前检查应用没有活跃会话，模型 ready 且不 busy。没有改变模型、系统提示或日常服务进程。

## 观察结果

| 阶段 | 明确文档请求实际检索 | 模块归属题 | 视觉上下文题 |
| --- | --- | --- | --- |
| attempt1：原代码 | 0/2 | 将 DINet 说成语音转文字 | 没有实际依据，未回答两张历史限制 |
| candidate1：明确请求预检索 | 2/2 | 将 FlashHead 说成 3D、StreamingTalker 说成语音合成 | 时间戳、最近两张图片与请求隔离回答正确 |
| candidate2：增加英文标识符回退 | 2/2 | 2D／2D／3D 核心归属正确，仍泛化音画同步职责 | 同上 |
| candidate3：合并中英文证据、修复尾部否定 | 2/2 | 核心归属正确，音画同步额外归属仍不准确 | 同上 |

“进行了检索”与“回答正确”分别检查。最终模块回答仍把音画同步笼统归给渲染器，而会话和浏览器媒体层也承担同步职责。检索摘要还会截断 README 表格中 StreamingTalker 的定义，SYSTEM 本来就包含三者职责，因此不能把正确归属全部归因于检索，也不能称整句事实完全正确。

其余四题的最终文本在四阶段完全相同。排障题仍先检查题目已确认正确的 ASR，没有检查实际提示／历史并独立重放；资源约束题没有质量评测步骤；架构比较仍有缺少测量条件的延迟概括。计算题四阶段均实际执行 `137*29+81` 并得到 4054，但回答含解释文字，不是仅输出数字。

这六题参与开发，没有独立留出集；每阶段只运行一次。2/2 是两个固定请求的执行情况，不是项目问答准确率或泛化结果。没有比较整体延迟或宣布模型能力提升。

## 修复范围

明确请求如 `请查阅项目文档：……` 或 `Please consult the project documentation for …`，在首个模型回答前执行现有只读 `search_project`。仅匹配窄的句首请求；中文形式需要标点分隔。普通对话、被引用的请求不会由此强制查阅，其他表达仍可由原模型自行选择工具。

预检索复用原工具状态、超时、取消、迟到结果丢弃及不可信数据标记，消耗原有最多三次工具预算中的一次。关闭工具时不预检索。触发与否定检查在 1024 字节问题提醒截断前进行，最终查询限制为 256 字符。常见中英文否定阻止自动预检索；这不是自然语言授权判定器，也没有禁止模型通过原路径自行提出工具调用。

检索保留原整词／空格分词优先级。没有命中时，同时考虑完整英文标识符和中文双字：每个不同标识符计 2 分，每个不同中文双字计 1 分，中文至少命中两个不同双字才计入。按覆盖度排序，选择最多 600 字符的摘要；这是小型文档目录的启发式检索，不是语义检索模型。

中间版本曾让任意英文命中阻断中文候选，导致 `Qwen视觉图片的采集时间和上下文历史如何管理？` 找不到正确文档。最终版本合并两类证据，Qwen/API 两种实际目录查询重新包含正确视觉文档；运行时裁剪后仍保留时间戳与两张历史依据。

- 四份原始结果的流式块拼接、最终文本、六条输入数量、每阶段七次模型请求和失败状态检查通过。没有修改或覆盖失败的中间结果。
