# MiniCPM-o 独立环境与持久部署计划

目标：让 VoxaStage 的端到端多模态后端能从完整依赖锁重建，验证真实流式输出，并将原临时目录部署迁移为可保留的独立运行目录。MindTalker 仍为单独项目，本轮不改其代码。

现场只读检查：禁用用户 site-packages 后，既有 Python3.10 环境核心包可以导入；不禁用时会混入用户目录的其他版本，因此新环境禁止继承用户包。历史临时目录中的 worker 已不存在，原两端口未运行。模型固定缓存仍可读取，现有 GPU 有可用空间。

选择从 torch2.11.0/CUDA13、transformers4.51.0、autoawq0.2.9、minicpmo-utils1.0.6 的既有核心版本解析完整哈希锁，使用新虚拟环境。相比复制旧 Conda 环境，避免无关包与用户包污染；相比更换模型或量化方式，减少验证变量。AWQ GEMM 的实际内核路径必须记录，不把可选扩展的差异隐藏成相同实现。

- [x] 解析完整依赖锁并审查；安装到独立新环境，不覆盖既有环境，不下载/改写已有权重。
- [x] 检查包版本、依赖闭包、用户包隔离、模型自定义代码与权重摘要；运行现有18项 worker 契约测试。
- [x] 复制已合并 worker/视觉代码与既有合成测试输入至专用目录，核验传输摘要；临时端口验证真实文字、原始语音、视觉联合输入、取消后恢复、男女声路由。
- [x] 检查流式首段早于完成、错误日志、GPU资源清理及模型前后摘要；失败保持记录，不冒充识别率或口型质量。
- [x] 验证通过后用持久目录恢复既有端到端入口，保留原配置和回退文件；补部署文档、脱敏证据和PR。

既有参考音色的可用性需先核验，缺失时不得用其他人物音色冒充既有角色匹配。完整独立GPU主机安装、真人录音与物理设备质量仍需单独验收；本机新虚拟环境不关闭这些缺口。
