# DINet 可配置消费提前量集成

目标：把已验证的等待策略接入原代理/worker流程，保留明确的0秒兼容模式和回滚配置，不复制或修改原生模型服务源码。

架构：`dinet-server/pacing.py`负责有界配置解析与单一公式替换；`launch.py`校验固定原生源码SHA，加载原有worker及WebSocket服务，保留生产心跳/准入/清理。部署者指定本地JSON配置，每个消费者启动时读取一次并记录配置SHA。请求期间固定该值，不接受浏览器的提前量参数。

- [x] 先写测试：0秒与原等待等价；0.4秒保留提前量且后续按200ms节奏；非法值/无效配置拒绝；不匹配表达式拒绝；一次请求内策略固定。
- [x] 实现配置schema：`{"version":1,"lookahead_seconds":0}`，范围0–0.8秒；缺失或损坏配置不默默启用优化。每次消费者读取至多1024字节。
- [x] 启动器仅支持已审计的worker/ws_service SHA，验证后注入自身助手函数。调用原服务启动函数，保留原代理路由及生产worker生命周期。测试错误版本在导入原生代码前拒绝。
- [x] 明确导出来源与说明，`export_demo.py`包含自身启动器/策略/测试，不包含第三方服务实现或运行配置。
- [x] 部署前保存supervisor配置和运行状态，原服务空闲才操作。安装版本化自身代码，先以0秒接管原worker命令；只重启空闲worker组，代理保留。独立超时保障及控制器异常均恢复原命令/状态。
- [x] 原代理路径先0秒预热/基线，再交错0与0.4秒，记录实际应用配置的日志、固定输入、浏览器时间线、取消恢复。通过后才保留0.4秒配置；失败则恢复原服务。
- [x] 审查结果、源码包与部署记录。人体感知、物理声学时间及更广泛质量仍单独待验；不以局部通过声称整个项目目标完成。

验收记录见[原代理集成](../DINET-PACING-INTEGRATION.md)：17次API检查、单列坏配置与恢复、10次正式浏览器对照；最终保留0.4秒。独立回滚预演及实际浏览器工具故障的恢复均留有记录。人体感知质量与物理声学边界仍未验收。
