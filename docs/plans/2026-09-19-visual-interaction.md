# 带时间戳的视觉语音交互

目标：让数字人理解用户提交的当前画面，并在下一轮比较前一画面；语音保留原始PCM，图像保留采集来源、会话内时间和轮次归属。按已授权阶段路线逐项验证，沿用本地优先和三种数字人输出。

设计选择：复用MiniCPM-o同一模型的图像、语音与文字输入，减少跨模型信息丢失。独立视觉描述器再喂给语音模型会引入摘要误差与另一套部署；连续视频/全双工改变更多变量，留在明确的后续范围。当前先实现按需快照，不宣称连续视频理解。沿用现有每会话600秒上限，相对采集时间范围0–600000ms。

## 一、模型能力与输入契约

- [x] 固定缓存源码核对：`streaming_prefill`接收PIL图像、numpy语音与字符串，第一语音块之前/之内只送一次本轮图片；后续语音块不重送图像。
- [x] `omni-server/visual_input.py`独立验证图像：JPEG/PNG，非动画，单张最多256KiB、1024×1024，整次请求最多2张。元数据限定id、采集来源upload/camera、会话相对时间captured_at_ms，不能把相对时间称为物理音画同步。
- [x] `worker.py`增加显式`--vision`开关与健康能力声明，未启用明确拒绝图片；保持默认语音部署兼容。图片作为用户消息可选附件，文字/语音二选一保持原契约，禁止助手附图。
- [x] 先写测试并观察失败：图像有效解码、越界/损坏/重复ID/过量拒绝、关闭视觉明确拒绝、多块音频只附图一次、健康状态如实声明；随后实现并回归原取消/音色测试。
- [ ] 原生环境启动视觉模型并测试固定图像+文字、图像+原始语音、两轮画面比较；记录模型版本、输入哈希、输出文字、PCM、耗时/显存、失败。保留原语音worker可恢复命令，空闲时替换，未验证不切默认。

## 二、会话与界面

- [x] 连接前读真实能力，MiniCPM视觉可用才显示图片提交入口；选择文件或用户主动打开摄像头、按需截图，展示本轮附件预览与移除。断开停止摄像头轨道。
- [x] 图片先在独立有界控件消息中验证/确认，再绑定下一轮文字或VAD完成的语音；确认后不随之后上传而改变正在生成的轮次。记录单调turn_id、图像ID、来源/时间，过期会话和迟到结果丢弃。
- [x] `ConversationHistory`保留最多两张最近画面、原有六轮/语音/文字边界，裁剪图片时明确提示，不把已删除图像伪装为可见；取消仍不保留未听完回答为完整历史。
- [ ] 协议/后端/前端分别测试边界、裁剪、打断与断线清理；真实浏览器图文、图音、多轮比较及三驱动输出验证。

## 三、对照评测与交付

- [x] 实现四条件串行评测工具：校验并固定输入内容、轮换请求顺序、区分预热与正式分母、保留失败和部分输出，未判读语义不计正确率；注入后端与HTTP模拟传输测试通过。
- [ ] 固定可复现的形状/颜色/空间关系探针与两帧变化，文本描述不泄露答案；语音单模态、图像加通用询问、图像与语音联合输入分别计分，预热与正式分开。
- [ ] 检查时间/轮次绑定、旧画面清理、重复输入、打断后的迟到结果；保留真实失败作为第四阶段方法对照候选。
- [ ] 部署说明、上游来源、范围限制、实验报告和演示材料随代码更新；不以协议通过代替感知或语义准确率。

验收顺序：先模型路径，再会话与界面，最后对照及展示。人工口型复核继续待办，不影响独立视觉能力验证，但不能据此宣布完整目标完成。

## 本地检查点

输入与会话代码已实现，关闭期间异步绑定和晚到摄像头/文件解码均有回归。真实WebSocket路由以模拟模型完成三轮图片绑定与裁剪。真实模型部署与语义对照仍待验证；模拟推理响应不作为模型质量证据。单元/集成测试数量与浏览器检查结果分别记录，避免把代码实现等同整阶段完成。
