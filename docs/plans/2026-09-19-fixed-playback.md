# 固定PCM播放基线

本任务细化既有第一阶段，不更改在线服务或宣称性能改进。

选用独立本地评测页，复用AvatarPlayer与渲染器，服务端使用已校验manifest中的固定PCM驱动真实Provider。相比重复文字合成，它控制了TTS变化；相比仅离线回放，它仍覆盖实时模型/适配器交付。先测实时驱动，必要时再用捕获序列做可控回放对照。

1. `avatar_playback_lab.py`：loopback HTTP/WebSocket入口，固定manifest/provider配置，限制单请求，超时与取消清理；同源检查；不从请求接受路径或后端URL。记录源文件/输入指纹，原始模型错误不返回浏览器。
2. `evaluation/playback.html`和`playback.mjs`：真实点击解锁音频，复用现有播放器及2D/3D渲染，记录接收、解码可用、安排起点、实际render回调的浏览器单调时间。服务端相对时间单列；不跨时钟直接相减。
3. 单元测试验证非法选择、失败隔离、并发拒绝和完成协议。真实浏览器固定PCM每个驱动重复三轮，记录所有失败及输入哈希。
4. 检查3D实际渲染画面；从相邻音源AudioContext时间计算空隙，按层分析对应帧间隔。将观察与人工音素质量判断分开，保留仍未完成的完整基线门槛。
5. 独立审查、适当回归、文档和私有草稿PR更新。
