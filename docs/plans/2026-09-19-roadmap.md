# 数字人与多模态工程路线

## 目标与阶段门槛

以现有三种数字人和两条语音链路为基础，形成可复现的评测、优化和多模态交互成果。基础模型归属保持清楚，所有改善必须有基线与对照。

1. **基线**：统一三驱动的输入清单、校验、重复运行和 JSON / Markdown 报告。先验收驱动适配层，再扩展到语音链路和浏览器。质量评估与传输同步分开；未测项目显式为空。不能用合成语音代替真实麦克风结论。
2. **优化**：根据基线选择一个实测瓶颈，在相同输入、相同环境与运行模式下对照，报告质量、延迟、资源代价。未证明改善的方案不替换默认。
3. **视觉交互**：视觉输入带采集时间、轮次和有界历史，支持当前画面与前一画面指代；以图像单模态、语音单模态和联合输入比较。先建立服务能力检查，不能假定已部署语音模型启用了视觉路径。
4. **针对性实验**：从失败样本选择一个问题，比较基线与方法变体。推理策略实验与训练实验明确区分；提供复现说明、消融和演示。

不同时展开多个未经验证的模型改动。每阶段保留通过/失败样本、版本、输入哈希和测量口径。仓库继续私有，运行素材与模型权重不随源码导出。

## 第一阶段设计：统一驱动基线

优先复用现有 Provider 适配器，新增独立评测入口，不修改在线服务与前端。替代方案是直接依赖各模型原生脚本（测量口径不统一）或立即加入全量浏览器测量（变量过多）；先建立可重复的适配层基线，后续分层补充。

- 输入：部署者提供 JSON manifest，含 case id、WAV 路径、SHA256、类别、来源、转写及人工核对状态。校验单声道 PCM16、8–48kHz、0–30秒。记录原始文件和24k播放 PCM 哈希；清单不含音色或模型密钥。
- 执行：选定一个 provider，串行运行；预热单独记录、不计入正式统计。分别支持快速送入和实时节奏；这两种模式不混算。生产适配器原有节奏控制仍生效，不将wall/audio比值称为裸模型RTF。
- 指标：首配对媒体到达时间、整段耗时、wall/audio比值、收帧间隔、PCM逐样本保持、帧序号、起始样本与PTS一致性、完整结束与取消后恢复。
- 报告：JSON逐次记录与Markdown汇总，按provider和case分组，统计成功数、失败数、样本量、P50/P95（线性插值）；失败不进入成功延迟分位数，但保留失败分母。
- 测量边界：接收媒体不是浏览器播放；音频相等和PTS连续不代表口型准确。口型同步、身份保持、视觉伪影、真实设备回声初始标记为未评估，后续另设人工标注与模型评估。
- 错误：开跑前覆盖旧成功标记，逐次原子保存；单次失败留下报告并继续其他预定case，最终非零退出。取消必须关闭异步生成器；输出不记录后端URL或原始帧。
