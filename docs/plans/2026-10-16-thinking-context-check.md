# 项目事实提示与思考模式对照计划

**目标：**解释固定短回复配置下反复出现的前提忽略、数据取舍和时序证据错误，比较事实背景与思考模式，而不因单次正确输出更换日常服务。

**设计：**同一本地Qwen3-4B、NF4/BF16、SDPA，生产SYSTEM与移除项目事实段的通用SYSTEM × enable_thinking开/关；两种SYSTEM都保留原基础规则和末尾的防编造规则。四条件共用temperature0.7/top_p0.8/top_k20/min_p0/repetition_penalty1，输出预算1024包含思考及回答。固定八道既有开发题、seed17/43，共64次，另一次非思考预热。参数一致用于控制变量，不宣称每模式最佳配置。

执行在隔离工作区内，沿用既有实验采集器与只读健康检查；日常服务不变。使用原采集器默认输入仍可复现前一轮，新增 `--manifest` 指定本轮输入，每条件可选择SYSTEM及思考标志，记录实际输入与kwargs。

## 任务

- [x] 运行前提交[输入与rubric](../benchmarks/2026-10-16-thinking-context-input.json)及计划；题目、评分点和采样参数不据结果改动。
- [x] 为条件配置与最终回答提取添加失败测试，覆盖思考结束标记跨块、结束标记后只有空白、未结束的思考、正常直接回答；保留原采集器失败注入测试。
- [x] 采集器支持输入清单和条件覆盖；任何metadata不泄露到model.generate参数。原默认行为保持兼容，新增完整原始token、思考结束与首个最终回答可见时间。只以最终回答评语义，未结束思考计无最终回答。
- [ ] 独立审查后执行64条。每题前与运行中检查日常会话，90秒时限，逐条保存，失败不覆盖；开始前至少8GiB可用显存。
- [ ] 审查全部最终答案；按四条件分别报告rubric、额外错误、EOS/长度上限、无最终回答与首个最终回答延迟。raw首文字常是思考，不等于用户响应；不以总分或思考中的正确片段代替最终答案。
- [ ] 整理结果、复现代码和部署决定，导出脱敏、链接检查与独立审查后提交PR。记录上轮PR22已合并，保持人工、声学和独立GPU部署验收未完成。

不因本轮结果重新命名开发题为留出集。项目事实段的移除本身改变输入长度和内容，若有效只能支持该整体干预；不能进一步断言是某个词或某个模型模块的原因。思考带来的正确率与最终回答延迟需同时考虑；本轮不实现或上线新的语音路由策略。
