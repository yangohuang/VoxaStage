# 复杂回答：领域词表与前提约束消融

目标：追踪已有复杂回答失败，判断领域词表和一般性前提约束是否影响同一模型的回答，不切换默认模型或提示。

设计：同一 Qwen3-4B 服务，领域词表有/无 × 前提约束有/无，四组条件。保留原四题，预先增加四个相关变体；共八题、四个任务族、32次正式请求。服务使用确定性解码，每条件每题只请求一次，不把重复确定性输出当独立样本。条件顺序按题轮换。另做一条短预热，独立记录。

输入与 rubric 固定在 `docs/benchmarks/2026-10-16-prompt-ablation-input.json`，生成预算256 token。提示约100字保持不变。新增变体属于人为编写的相关探针，不能作为广泛测试集；条件提示均不直接提供参考答案。语义审查标记为助手审查，不冒充真人盲评。

实施步骤：

- [x] 固定输入清单并提交，记录输入SHA256和当前服务源文件SHA256。
- [x] 检查应用无活动会话、模型ready且不busy；每次请求前重新检查，有用户占用则停止，不抢占或重启。
- [x] 串行收集NDJSON文字增量、首个非空文字延迟、总耗时、完整响应、异常及请求顺序；每条完成立即落盘，不覆盖旧记录。
- [x] 对每条回答按预先rubric审查，分开记录前提、事实、约束与完整性；无法判断的内容不标通过。当前接口未给出EOS/token数，不能仅凭HTTP结束宣布未截断。
- [x] 汇总按条件和任务族的差异，保留失败、不夸大因果范围，不将文本HTTP时延当声学端到端性能。
- [x] 独立审查、检查链接与导出脱敏，提交实验报告。只有证据明确才能提议上线；本实验本身不修改日常服务。

第一阶段的人类音画观察、物理声学测量以及完整独立GPU部署仍待验收；本次实验不关闭这些门槛。

执行结果与局限见[报告](../PROMPT-PREMISE-ABLATION.md)。运行脚本初始参考了历史服务文件，随后通过监听进程映射确认实际源码与主分支一致，运行证据以实际服务文件为准。
