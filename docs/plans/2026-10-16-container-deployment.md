# 隔离 GPU 部署复现计划

目标：逐项补齐独立安装与真实后端联动证据，保留人工音画、物理声学、真实输入和空白主机验收范围。先完成日常 Qwen3-4B 的干净容器安装，再推进其余后端与应用；单 worker 通过不代表整站部署完成。

本阶段使用现有授权 GPU 主机、固定摘要的 Python 3.12 Debian 用户空间、原有完整 SHA256 依赖锁和只读核验模型。不复用宿主 Python 包，不切换日常模型，也不停止其他服务。共享内核和驱动的限制仍保留。

## 第一步：构建与安装隔离

- [x] 独立工作树基线 `efe0234`；固定基础镜像摘要与 libgomp1 版本。
- [x] 构建文件独立复核；使用只含 worker、锁与构建文件的上下文，缓存版本额外包含原始 wheel。
- [x] 保留下载超时、截断 wheel 哈希拒绝、部分缓存仍走索引的失败记录。
- [x] 完整 63 包 wheelhouse 经锁内哈希验证；Python 安装步骤禁止网络并运行 pip check；不复制宿主已安装包。
- [x] CPU 探针验证 Python 3.12.15、独立包路径、非 root 身份与实际延迟导入；修复数字 UID 缓存初始化问题。

## 第二步：真实推理与协议回归

- [x] 单 GPU 至少 8 GiB 空闲；模型 10 个核心文件核验后、启动前再次检查准入；运行期间持续监测日常服务。
- [x] 完整控制器使用全容器 ID、不可变镜像 ID 和非空标签核验所有清理；故障为粘性状态；CPU 测试与真实 Docker 故障演练通过。
- [x] 独立临时容器无网络、不发布端口、只读根目录与模型、受限 tmpfs；客户端在容器内运行。
- [x] 固定 17 次请求：1 预热、3 类语言各 3 次、1 长回复、3 组关闭流/恢复。保留全部增量与输入，失败启动批次单独保存。
- [x] 长回复 199 个片段；3 次关闭流后均观察 idle，随后恢复请求成功；不将 HTTP 观察解释为 GPU 强制取消证据。
- [x] 10 个模型文件前后哈希一致；正常批次容器退出 0 并移除；原有服务健康、空闲。

200 ms 是健康探测完成后的间隔，每次探测有 5 秒整体期限，不是 200 ms 的中止保证。协议通过不等于回答质量通过，文字输入不等于 ASR 质量。
