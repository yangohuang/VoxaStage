# 固定提示的模型与解码对照计划

**目标：**针对已复现的前提忽略与约束回答缺陷，区分模型替换、输出预算与采样策略的作用，保留可复现的正负结果。

**结构：**独立工作区内的离线采集脚本，依次加载已在本地存在的 Qwen3-4B 与 Qwen3.5-4B 文本模型；复用日常 NF4 双重量化、BF16 计算与 SDPA，不修改服务或应用代码。输入包含固定的生产 `bot.SYSTEM`，不添加 Agent 工具提示，因而不能把绝对结果与此前 Agent 实验直接比较。

**执行：**在当前任务内分步执行、逐项验证；沿用项目 `docs/plans` 的实验计划位置。完整阶段目标中的人工、物理声学与独立机器部署门槛不变。

## 预先固定的实验

- [输入](../benchmarks/2026-10-16-model-decoding-input.json)：三道历史复杂题、五道新增任务题及逐题 rubric；不根据本轮输出修改题目或提示。
- 每模型八题 × 五次生成 = 40 次正式请求：greedy/256、greedy/512，以及共同采样参数/256 的三个固定 seed；两模型共80次，另各一次预热。
- 采样使用 temperature=0.7、top_p=0.8、top_k=20、min_p=0、repetition_penalty=1。参考两模型官方非思考模式通用参数，未实现 Qwen3.5 额外 presence penalty，不宣称复刻全部官方最佳配置。
- 所有条件关闭 thinking，模型自身 tokenizer/chat template 保留并记录哈希。不同 tokenizer 的256 token不表示完全相同的字符预算；两种模型的量化效果与内核也不能视为完全等价。
- 每模型题目顺序固定，奇数题翻转条件顺序，三个采样seed轮换。模型依次加载而非随机交错，因此耗时只作当前实现观察，不作硬件无关排名。

## 实施和验收

- [ ] 在运行前提交输入与本计划。
- [ ] 实现 `docs/benchmarks/2026-10-16-run-model-decoding.py`：模型路径与结果路径由命令行传入；禁止覆盖结果，先记录待执行条目，逐条原子保存。记录环境版本、模型文件SHA256、模板、实际输入token、输出token和EOS/预算/停止原因、首个可见文本时间、总耗时及进程显存峰值。异常保留类型和已有输出。
- [ ] 先写并运行 `docs/benchmarks/test_model_decoding_capture.py`，验证请求矩阵、结束原因和不可覆盖/失败保存契约；测试不能模拟语义质量通过。
- [ ] 开始前至少8GiB可用显存；每条生成前检查日常应用无活跃会话、LLM未忙。生成时设置时限并监测活跃会话，有占用则停止本实验。两个模型逐进程运行，实验结束释放模型。
- [ ] 完成两模型真实流式生成，按 rubric 审查全部结果，报告每类题目和截断，不把三个seed当三个独立题目；不把输出更长当正确。
- [ ] 输出 `docs/MODEL-DECODING-COMPARISON.md` 与原始结果/审查JSON；记录模型回退内核及环境限制。执行导出、脱敏、链接校验与独立审查后提交PR。

若候选在历史排障／约束题仍失败，或新增题发生重要回归，不据总分上线。即使文字候选达标，后续仍须工具链路、语音延迟与数字人联动验证。
