# ASR 历史证据评分计划

目标：补充第一阶段语音输入基线，将已有同输入、四配置的真实识别记录转成可复算报告。继续执行既有基线设计，不改在线模型和服务。

设计：标准库离线评分器读取 JSON。每条记录明确配置、样本 ID、参考文本来源、是否人工核对、识别状态和输出。归一化采用 NFKC、casefold、去 Unicode 标点和空白；保留其他符号。编辑距离使用字符单位，汇总按参考字符数加权。人工参考与合成提示词分开统计，后者只称提示词差异率。缺失、重复或不同配置参考不一致均拒绝；失败结果保留尝试数分母，另报参考字符覆盖率，不伪装成空转写或零错误。文本差异率只针对有成功结果且参考非空的子集，未完整执行不得当作全量比较。静音单独统计非空输出。

实施步骤：

- [x] `evaluation/test_asr_scoring.py`：先验证加权分母、大小写标点、中英混合、静音插入、失败/缺失样本和参考分组，确认新功能缺失时失败。
- [x] `evaluation/asr_scoring.py`：实现 `score(records)` 和 JSON CLI；无第三方依赖、无网络、无模型调用。CLI 输入和输出不得为同一路径。
- [x] 使用现有三条合成语音的 12 条历史识别结果，保存输入文件 SHA256 和来源摘要；明确当前哈希不证明当年请求字节完全相同，不将历史模型耗时解释为当前端到端性能。
- [x] 保存可发布的纯文本输入和报告，不包含语音、人像、服务地址或个人路径；补文档和状态入口。
- [x] 跑新增与现有 evaluation 测试、源码导出和独立结果核对；保留第一阶段人工/物理验收缺口。

完成门槛：四配置参考集合完全相同；报告可由导出源码离线重建；不把训练/提示词对齐、协议通过或服务内部耗时当作人工质量和声学验收。

验证：22 项 evaluation 测试通过（含 10 项新增）；独立导出环境的 10 项评分测试通过，报告 JSON 重算一致。独立审查核对 961 对字符串编辑距离及 CLI 覆盖输入边界；修复部分失败的分母说明并复核通过。
