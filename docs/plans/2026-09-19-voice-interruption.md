# 自动语音打断基线

使用现有浏览器页面和真实对话后端，在WebSocket PCM输入边界串行送入两段固定16k音频；第二段仅在第一轮确实播放时送入。复用现有观察探针记录generation、音源stop和安排时间。

这用于验证声音触发的VAD/轮次切换，不是按钮打断。输入块和样本区间可精确关联发送时刻，但它绕过物理麦克风采集/DSP，因此不称为精确麦克风捕获延迟。该缺项继续明确保留。

1. 新增独立`evaluation/voice-round.js`，在连接前安装socket观察，输入严格PCM16、16k、时长/缓冲有界，按20ms节奏发送，记录样本边界。
2. 首段长问题→首轮播放→第二段短改口→语音触发reset（端到端`speech_started`、级联`interrupted`）→旧源停止→第二轮恢复/已观察片段排空/idle。所有失败清理连接并保留分步状态。
3. 单元测试验证输入边界、失败与时序判定；真实两后端×三驱动串行测试，保留输入哈希和所有失败。
4. 记录虚拟输入与真实采集边界；不由这项功能测量推断ASR总体错误率、声学回声或口型准确性。

已完成：最终六组合交互检查通过，11项新增测试通过，所有早期失败保留。级联三条严格输出约束失败，端到端三条通过，独立于交互检查统计。详见[实测与边界](../VOICE-INTERRUPTION-BASELINE.md)。
