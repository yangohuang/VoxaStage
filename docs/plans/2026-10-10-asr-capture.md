# ASR 请求采集计划

继续第一阶段的输入评测。历史评分缺少请求时音频哈希和完整术语配置；本次在已有本地 `/transcribe` 协议上补采集器，保持线上推理实现不变。

设计：一次运行针对一个明确模型端点，对一个固定 WAV 清单交错运行多种术语配置。输入先按清单校验 SHA256、PCM16/16kHz/单声道、30秒上限，再冻结为实际发送字节。每配置预热一次，正式轮次与预热分开。报告保留实际请求字节摘要、术语文本、声明与服务报告的模型版本、成功/失败、客户端请求耗时与服务内部耗时。未知版本保持未知；客户端耗时不是麦克风端到端延迟。输出在独立新目录逐请求保存，参考文字不发送给 ASR。

所有配置使用同一模型端点；不同模型分别运行，不能在采集中自行切换服务。采集器不升级当前话轮 ASR 为流式 ASR，也不改变现有流式回复。

步骤：

- [x] 先写测试：输入哈希与格式、路径边界、同一冻结字节、配置轮换、失败计数、超时、模型不匹配、响应长度限制、取消后的证据、空输出及人工参考标识。
- [x] 实现 `evaluation/asr_capture.py`：清单读取、有限 HTTP 请求、原子 JSON 保存、评分输入及评分结果；复用 `asr_scoring.py`。

验收：协议测试不得冒充模型成绩；报告必须能区分预热/正式、失败/空转写、声明/实测、合成提示词/人工听写；没有隐藏的模型下载、重启或上游代码修改。

验证记录：9 项采集器测试及全部 31 项 evaluation 测试通过。独立审查发现并修复 context 首尾空格会被真实 HTTP 库拒绝的问题，新增失败后通过的回归；复核通过。报告补 endpoint 与已有健康元数据，同时明确 model_configuration_complete=false。
