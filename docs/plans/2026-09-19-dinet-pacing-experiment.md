# DINet 消费提前量受控实验

目标：验证既有部署首次五个200ms块后的追赶等待是否导致约250ms供帧间隔。只改变消费者等待公式：`start + blocks * 0.2 - now` 减去固定提前量，保留原有前五块启动条件。预设0、0.4、0.8秒；不调整模型、图片编码、客户端预送或浏览器预缓冲。

这属于正式上线前的隔离实验，动态人工质量基线仍未验收。扩大浏览器缓冲会增加首声延迟，无限提前消费会增加队列压力，故先验证有界提前量。

1. 检查原服务空闲。实验服务不向生产代理注册心跳；源文件SHA固定，只在独立进程内替换等待表达式，原文件不修改。
2. GPU余量不足时暂时停止一个空闲且已缓存模型的worker，保存原PID/状态。外层控制器无论成功或失败均终止实验进程并启动原worker；设总超时及独立回滚保障。其余worker和代理不改动。
3. 同一实验进程内，预热后交错对比三种提前量，各重复三次中文固定PCM。记录首媒体、逐帧头/编码/配对媒体时间、原PCM一致性、原生消费队列及块级等待。保留所有失败，不只导出最好一轮。
4. 只有确实改善供帧后，才追加长音频、停顿、取消恢复和真实浏览器对照；捕获原媒体用于质量差异复核。性能捕获与落盘质量捕获分开。
5. 实验成功仍不直接改变默认服务：报告延迟、队列、取消、质量边界及退化情形，通过审查后再决定集成。若假设未获支持，记录反例并回到归因。
