# 独立 TTS worker 与部署验证

继续执行用户已授权的本地优先、流式优先及独立部署目标。按 executing-plans 在本会话逐项验证。

## 设计

当前 TTS 依赖已部署服务的业务集成代码，公开音色兼容层不能独立启动模型。
新增不依赖该服务的 worker，使用官方 IndexTTS 2.5 固定源码
`a371df7d0746a0ae7fdf075798b6b04e34a0132e`，保留应用已有协议。
模型、声码器、分段算法属于上游；本项目负责服务协议、背压、取消、音色映射和采样率适配。

候选路径：复制现有服务无法保证公开来源；引入本地 vLLM 分支需要先整理未提交改动及来源；
官方原生版本可固定来源且依赖边界清楚，作为部署基线。它是分段流式，不能宣称 token 级实时合成。

`tts_runtime.py` 管理单模型线程、最多四个待发送音频包及流式22.05k→24k重采样。
`tts_server.py` 实现 localhost HTTP/WS 协议；管理员 JSON 指定音色和参考 WAV，浏览器只能选 ID。
`tts_native.py` 延迟导入官方模型、检查本地资源、固定推理选项。启动失败不能报告 ready。
断连只请求协作停止，已开始的 GPU 运算可能继续；模型线程退出前保持 busy。
错误只能返回有界公开说明，不返回文件路径或模型异常原文。
