# 独立 TTS worker 与部署验证

继续执行用户已授权的本地优先、流式优先及独立部署目标。按 executing-plans 在本会话逐项验证。

## 设计

当前 TTS 依赖已部署服务的业务集成代码，公开音色兼容层不能独立启动模型。
新增不依赖该服务的 worker，使用官方 IndexTTS 2.5 固定源码
`a371df7d0746a0ae7fdf075798b6b04e34a0132e`，保留应用已有协议。
模型、声码器、分段算法属于上游；本项目负责服务协议、背压、取消、音色映射和采样率适配。

候选路径：复制现有服务无法保证公开来源；引入本地 vLLM 分支需要先整理未提交改动及来源；
官方原生版本可固定来源且依赖边界清楚，作为部署基线。它是分段流式，不能宣称 token 级实时合成。

`tts_runtime.py` 管理单模型线程、最多四个待发送音频包及流式22.05k→24k重采样。
`tts_server.py` 实现 localhost HTTP/WS 协议；管理员 JSON 指定音色和参考 WAV，浏览器只能选 ID。
`tts_native.py` 延迟导入官方模型、检查本地资源、固定推理选项。启动失败不能报告 ready。
断连只请求协作停止，已开始的 GPU 运算可能继续；模型线程退出前保持 busy。
错误只能返回有界公开说明，不返回文件路径或模型异常原文。

## 验证步骤

- [x] 核对现有协议、官方源码及本地改动；基线 `python -m unittest test_backend -q` 5项通过。
- [x] 先写 `test_tts_server.py`：拒绝错误音色/身份/顺序，验证提前输出、断连仍占锁、恢复、错误终止和有状态重采样；运行观察缺失实现失败。
- [x] 实现三份模块；运行新测试和已有 backend/lifecycle 回归。测试模型替身只验证协议，不作为真实合成证据。
- [x] 固定官方源码、模型与辅助资源来源；独立安装依赖，使用两种官方公开参考音色真实合成与中途关闭后恢复，保存首 PCM 时间、样本数、采样率、模型标识和资源退出证据。
- [x] 更新部署说明和导出清单，审查与脱敏后交付 PR。未经实际安装和模型验证，不标记独立部署通过，不切换日常服务。

全新 GPU 主机、人工声音/口型、物理麦克风扬声器及更广输入仍是原目标的独立验收项。

当前检查点：两个独立环境的154包重建、依赖一致性、隔离位置及模型类导入通过；各自27项模型适配/协议/真实回环客户端测试通过。14个模型文件匹配官方固定版本；RTX 4090 实际模型加载20.81秒，进程退出后空闲显存恢复到测试前水平。在线安装曾因 TLS 响应不完整而失败，后通过固定哈希的本地 wheel 恢复，详见[验证记录](../TTS-STANDALONE-VALIDATION.md)。补充公开参考音色的6次真实合成（含2次断连后的恢复），首PCM和输出时长已记录，竞争请求返回409、占用释放及恢复正常。已有客户端、真实Chrome播放/打断/恢复与StreamingTalker网格更新通过，6条保存记录和中断上下文核对通过。另完成同一真实模型的50毫秒注入超时恢复、30轮顺序请求及120轮内存诊断；功能和线程生命周期通过。RSS诊断证明存在可归还的分配器空闲页，未宣称排除所有泄漏。独立worker实现交付复核通过。生产角色音色、人工质量、其他数字人驱动、默认90秒超时及长期内存趋势仍待验证，日常服务未切换。
